A convolution is a small calculation repeated in many places. Start with four multiplications you can see, then learn how shape tells you how many times to repeat them. Each formula below comes with its meaning, a worked example, and a way to test your understanding.

1 · A shape is a labelled address system for numbers

A scalar is one number, such as 7. A vector is a row or list of numbers. A matrix is a rectangular grid. A tensor is the general name for an array with any number of axes. You already understand the essential idea: a spreadsheet has rows and columns; a batch of colour images needs more labels. A tensor’s shape lists how many slots there are along each axis. Shape tells you where a number can be stored, not what the number’s value is. [Review pp. 32–35]

A 2×3 matrix has two rows and three columns: six stored numbers. Its shape is (2,3). Multiplying 2×3 counts slots; it does not multiply the six values inside the matrix. This distinction is the reason a convolution question can ask for both the output values and the number of output elements.

The review uses NCHW order: (batch, channels, height, width). The example (2,3,4,5) means two images, each containing three grids, each grid four rows high and five columns wide. It stores 2×3×4×5=120 numbers. For one image, CHW=(3,4,5) stores 60. RGB is a familiar three-channel input: separate red, green, and blue values at each pixel. Later channels are calculated feature responses, not necessarily colours or recognisable objects. A feature map is one spatial grid of such responses; its entries are activations. [Review p. 34]

Some software writes NHWC=(2,4,5,3). That changes the order of the labels, not the total 120 entries. Never read the first number as channels until the axis order is given. Also, batch size is not network width: increasing N repeats the same model on more examples.

Try: what does (4,2,3,5) mean, and how many numbers does it contain?
  1. N=4 images; C=2 grids per image; H=3 rows; W=5 columns.
  2. One grid has 3×5=15 entries.
  3. One image has 2×15=30 entries.
  4. The batch has 4×30=120 entries. The equality with the earlier example’s count does not make the shapes interchangeable.

2 · A kernel makes one output by multiplying a patch and adding

A weight is a coefficient in a calculation. A kernel, in the spatial sense used here, is a small grid of weights. A patch is the matching small region of input values under that grid. Place the kernel over the patch, multiply corresponding positions, then add the products. This repeated local calculation is what a CNN calls convolution. We use the deep-learning cross-correlation convention: the kernel is not flipped. Mathematical convolution can use a flipped kernel, so follow the convention stated by the problem. [Review pp. 33–34] [Conv2d, operator]

Take patch [[1,2],[5,6]] and kernel [[1,2],[0,−1]]. Read matching positions in the same order. Top left: 1×1=1. Top right: 2×2=4. Bottom left: 5×0=0. Bottom right: 6×(−1)=−6. Add: 1+4+0−6=−1. The result is one scalar, not a 2×2 output. Four input values collapse into one response.

That calculation is a dot product: pair matching entries, multiply, and add. The symbol Σ means “add all the terms described after me.” Writing Σxiwi is shorthand for x1w1+x2w2+…; it is not an extra mysterious operation. An index such as i tells you which entry to use. A bias is a learned offset added after the sum. Bias 2 would change −1 to 1.

Now move the same weights one column right. The new patch is [[2,3],[6,7]]. The sum becomes 2×1+3×2+6×0+7×(−1)=2+6+0−7=1. The weights were reused; only the input patch changed. Continue to build the whole output grid. Kernels can learn useful local patterns, but these hand-chosen weights are teaching examples, not a trained edge detector.

    3 · Output shape counts the places where the window fits

    Stride is the distance between successive window anchors. Stride 1 moves one position at a time; stride 2 moves two. Padding adds a border, usually zeros, so a kernel can inspect boundary regions. Padding P=1 adds one row above and below and one column on each side. It adds two to each spatial size, not one, and not two times the entire image area.

    Derive the row count before memorising the formula. A length-4 input and length-2 kernel have valid starting rows 0,1,2: three positions. The last start is 4−2=2. With stride 1, the starts are 0 through 2, giving (4−2)/1+1=3. The +1 counts the first start at 0. With stride 2, the starts are 0 and 2, giving (4−2)/2+1=2. If the last start is not exactly reachable, you round down: you cannot place half a window.

    Hout = floor((Hin + 2Ph − Kh)/Sh) + 1

    Wout = floor((Win + 2Pw − Kw)/Sw) + 1

    floor means the largest integer no greater than the value: floor(3.5)=3. This formula assumes dilation 1 and equal padding on opposite sides. A kernel dimension must fit inside the padded input; otherwise this is invalid geometry, not a tensor with a negative number of rows. Compute height and width separately when they differ. [Review pp. 18, 34, 47]

    Worked rectangular example, constructed. Input H=5, W=7; K=3×3; S=2; P=1. Height: floor((5+2−3)/2)+1=floor(4/2)+1=3. Width: floor((7+2−3)/2)+1=floor(6/2)+1=4. The output has 3×4=12 positions per map. It is not square merely because the kernel is square. With four filters it becomes C×H×W=4×3×4; with batch 2, NCHW=(2,4,3,4).

    Why the floor matters. H=8, K=3, P=0, S=2 gives floor(5/2)+1=3. The valid anchors are 0,2,4. An anchor at 6 would need rows 6,7,8, but the final input row is 7. It cannot fit. Rounding 2.5 upward would invent an invalid fourth window.

    Dilation, optional extension. Dilation D spaces the kernel’s taps apart. A three-tap kernel with D=2 touches offsets 0,2,4: it spans five positions while still containing three weights. Replace K by the effective kernel size Keff=D(K−1)+1. A 3×3 kernel at D=2 spans 5×5 positions but still has nine coefficients per channel slice. The calculator includes this extension; the basic review examples use D=1. [Conv2d, dilation and Shape]

    4 · One filter adds contributions from all its input channels

    So far the input had one channel. An ordinary convolutional filter for an RGB image contains three spatial kernel slices: one for red, one for green, one for blue. It computes three local dot products at a position and adds them, then adds one bias. Those partial sums become one output entry. They do not become three separate output maps. A complete filter sees the whole input depth. [Review p. 34]

    Constructed two-channel example: channel 1 patch [[1,2],[0,1]], slice 1 [[1,0],[1,−1]] gives 1+0+0−1=0. Channel 2 patch [[3,0],[2,1]], slice 2 [[0,1],[2,1]] gives 0+0+4+1=5. Add both contributions and bias 2: 0+5+2=7. A different complete filter could use different slices and yield a different response at the same position.

    Here is the general sum translated into actions, with one image index n, output-filter index o, and output position (r,c):

    Y[n,o,r,c] = b[o] + Σinput channels i Σkernel rows u Σkernel columns v W[o,i,u,v] · Xpadded[n,i,rSh+uDh,cSw+vDw]

    1. Choose one image n and one complete filter o.
    2. Choose the output row r and column c. Multiply by stride to get the input window’s starting position.
    3. For each input channel i, visit each kernel row u and column v. Dilation spaces those visits apart.
    4. Multiply each input value by its matching weight; add every product from every connected channel.
    5. Add the filter’s bias once. Put that one result into Y[n,o,r,c].

    For ordinary convolution, the weight tensor is (Cout,Cin,Kh,Kw). Four filters, three input channels, 3×3 slices means (4,3,3,3): 12 spatial slices and 108 weights, producing four maps. Neither batch nor image height appears in that weight shape. [Review p. 34]

    Lab 3 · Add channel contributions into one output

    Keep the first slice fixed. Multiply all four weights in the second slice by a gain, then add the bias. The input still has two channels when gain=0; zero weights alone do not rebuild a smaller layer.

    Groups change the connections. With G groups, each output filter sees Cin/G input channels. Both Cin and Cout must be divisible by G. For Cin=4, Cout=6, G=2, each filter sees two channels; there are three output filters in each group. Its 3×3 weight count is 6×2×9=108, half the ungrouped 6×4×9=216. Depthwise convolution in the review’s basic case uses G=Cin=Cout: one spatial slice per channel. Eight channels with 3×3 slices need 8×9=72 weights. A following 1×1 pointwise convolution mixes channels; count it separately if present. [Review, parameter/MAC tables] [Conv2d, groups]

    5 · Parameters count the rule; activations count answers; MACs count repeated work

    A parameter is a learned value stored in the model. In these resource formulas, “weights only” excludes biases. A MAC, multiply–accumulate, means multiplying an input by a weight and adding it to a running sum. Counting MACs is a convention for the main dot-product work; it need not exactly equal the number of separate additions in a hand-written sum. The review counts one MAC per weighted term and omits bias addition and pooling comparisons. [Review pp. 21–23, 55–60]

    Apply the rectangular example from section 3: N=2, Cin=3, Cout=4, output 3×4, K=3×3, G=1. One filter needs 3×9=27 coefficients. Four filters need 4×27=108 weights; with biases, 108+4=112 parameters. Outputs: 2 images×4 maps×3 rows×4 columns=96 activations. Each activation needs 27 weighted terms, so 96×27=2,592 MACs. This order makes the MAC formula understandable: count how many answers, then count the work per answer.

    Larger spatial maps reuse the weights more times; they do not create new weights. Doubling H and W approximately quadruples output activations and MACs when other settings stay fixed. Exact stride/padding floors can change that ratio. The parameters stay the same. Doubling batch N doubles activations and MACs, also without changing parameters. Doubling filters doubles parameters, output activations, and MACs. These are different edits, even when some totals change by the same factor.

    To change counts into storage, specify a bit width q. Bytes=number of entries×q/8 if entries are densely packed and metadata is ignored. The 112-parameter example in FP32 (32 bits=4 bytes) occupies 112×4=448 bytes of parameter data. Its 96 outputs occupy 384 bytes. Those are different memory objects; actual inference also needs live inputs and possibly temporary workspaces.

    FLOPs count floating-point arithmetic work. Under the review’s two-operations-per-MAC convention, 2,592 MACs correspond to 5,184 FLOPs. FLOPS, with S meaning “per second,” is a rate. Dividing 5,184 FLOPs by a hypothetical sustained 1,000,000 FLOPs/s gives 0.005184 seconds=5.184 milliseconds of arithmetic time under that assumption. It is not measured latency: data movement and execution overhead also matter. [Review pp. 38–61]

    Try: N=3, input channels 2, output channels 5, output map 4×6, 3×3 kernel, G=1. Count weights, bias-inclusive parameters, outputs, MACs.
    1. Weights per filter=2×3×3=18. Five filters: 90 weights.
    2. Add five biases: 95 parameters.
    3. Output entries=3×5×4×6=360.
    4. Work per output=18 MACs. Total=360×18=6,480 MACs. At two FLOPs/MAC: 12,960 FLOPs.

    6 · A dense layer uses the same dot-product idea without sliding

    A dense or fully connected layer connects every input feature to every output neuron. A feature here is one number per example. If one example has three features and you want two outputs, create two rows of three weights. Each output row does one dot product with the same input vector. Convolution shares a local rule across positions; a dense layer operates on the full input vector. [Review pp. 3–5, 32]

    Constructed example: x=[2,−1,3]. Weight row 1=[1,0,2], bias 1; row 2=[−1,3,1], bias 0. Output 1 is 2×1+(−1)×0+3×2+1=9. Output 2 is 2×(−1)+(−1)×3+3×1+0=−2. The output is [9,−2]. There are six weights, two biases, eight learned parameters, two output values, and six MACs for one example.

    For N examples with Cin features and Cout neurons: input X has shape (N,Cin); weights W have shape (Cout,Cin); bias b has shape (Cout); output Y has shape (N,Cout). Matrix notation writes Y=XWT+b. The superscript T means transpose: swap W’s row and column axes so the matrix dimensions match. The bias vector is reused for every example, an operation called broadcasting.

    The review’s actual Q1 gives N=4, Cin=2, Cout=6. W=(6,2); weights=6×2=12; plus six biases gives 18 parameters. The 4 is a batch count, so it is not multiplied into 18. If additionally asked, Y=(4,6), activations=24, MACs=4×6×2=48. [Review pp. 3–5]

    Lab 4 · Watch two dense neurons use the same features

    Fixed weight rows: [1,0,2] and [−1,3,1]. Fixed biases: 1 and 0.

    Matrix-multiplication exam rule. An (m,k) matrix multiplied by a (k,n) matrix produces (m,n). The shared inner dimension k counts the weighted terms per output. There are m×n outputs, each with k MACs, giving m×n×k MACs. Example: (2,3)×(3,4) gives (2,4), eight outputs, three terms each, 24 MACs. It cannot be multiplied if the two inner dimensions differ. [Review pp. 21, 55]

    7 · Pooling chooses or averages numbers inside each channel

    A pooling window reduces spatial resolution with a fixed rule. Max pooling returns the largest number in a patch; average pooling returns its arithmetic mean. Neither uses a learned kernel of coefficients in the ordinary pooling layer. Pooling runs separately on every channel: it does not combine RGB into one channel. Its output batch and channel counts are unchanged. Use the same window-fitting reasoning to find Hout and Wout; the basic examples use padding 0. [Review p. 35]

    On [[1,2],[5,6]], max is 6; average is (1+2+5+6)/4=14/4=3.5. A 4×4 map pooled with a 2×2 window and stride 2 becomes 2×2. For input (2,4,8,10), that pooling produces (2,4,4,5): output elements=160, learned parameters=0. Under the review’s weighted-MAC accounting, max-pool MACs=0; finding a maximum still requires comparisons. “Zero parameters” and “zero MACs” do not mean “zero execution time.”

    An activation function changes each value using a rule. ReLU(x)=max(0,x) keeps positive values and replaces negative values with zero. It normally keeps tensor shape unchanged. Pooling instead changes spatial size. Convolution, ReLU, and pooling are three different stages; never add the pooling window size to the convolution parameter count.

    8 · Propagate shape before filling a network’s resource table

    Flatten rearranges one example’s C×H×W tensor into a vector of C H W entries. It does not sum the values and does not flatten the batch into one example. A tensor (2,6,2,3) becomes (2,36), not (72) and not (2,6). Global average pooling would instead reduce each channel to one value; that is a different architecture and a different dense input size.

    The safest exam order is: write each input shape; calculate spatial output shape; set output channels from the layer; count its weights; count output elements; multiply by weighted terms per element for MACs. Then use that output shape as the next layer’s input. Do not restart the second convolution with the original image’s channel count. [Review pp. 16–23]

    Total activations versus peak memory. Summing all output entries measures how many numbers stages generate. Peak live memory asks which tensors need to exist together. In a simple sequential model, one approximation is the largest adjacent input-plus-output pair; extra workspaces, branches, and reuse can change it. The review’s AlexNet total 932,264 includes its 150,528 input entries; outputs alone total 781,736. Its adjacent-live estimate 440,928 is input 150,528 plus first-convolution output 290,400.     Why memory is imbalanced. Early maps cover many spatial positions; later pooling reduces area. Halving H and W divides area by four. If channels simultaneously double, activations change by 2/4=1/2, not by 2. Dense layers may instead have many distinct weights because every flattened input connects to every output. In the source’s extended diagram, 64×64×64=262,144 flattened inputs to 100 neurons requires 26,214,400 weights. This is why “most parameters” and “most activation memory” can describe different layers.

    ★ Compression is useful only when the smaller model still solves the task

    You now know what a convolution does and how its shape produces resource counts. The next question is why those counts matter. A model may need more storage, working memory, computation, or electrical energy than its intended device can supply. Model compression changes the model to reduce one or more of those requirements. Accuracy measures whether its predictions are correct on a defined evaluation set. A compressed model can save resources and also make more mistakes. That tension is the efficiency–accuracy tradeoff in the starred review slides. [Review pp. 24–26]

    Think of packing for a trip: removing items makes the bag lighter, but removing the passport makes the trip fail. First identify what must still work. Then compare the cost of choices that satisfy that requirement. “Smallest” becomes meaningful only after you specify a resource and a minimum acceptable quality.

    Neural architecture search (NAS) searches among different network designs: for example, different numbers of layers or channels. An architecture is the arrangement and sizes of the network's parts; its learned weights are the numerical coefficients within those parts. NAS can find a cheaper arrangement rather than merely deleting entries from one fixed arrangement. A lower arithmetic count is evidence of less counted work. It does not prove lower elapsed time on every device, because devices execute different operation patterns differently.

    Practice 1 — Constructed: a device requires accuracy ≥90% and latency ≤10 ms. A: 91%, 12 ms; B: 90.5%, 8 ms; C: 88%, 5 ms. Which qualifies?
    1. Apply both constraints to each model. A meets accuracy but fails the time limit. C meets the time limit but fails accuracy.
    2. B satisfies 90.5≥90 and 8≤10, so B is the only feasible model.
    3. C is fastest among these observations, but “fastest” alone does not satisfy this task. The values are constructed, not read from a slide plot.

    Exam recipe: name the desired resource saving, name the quality constraint, and explain what evidence supports each. If accuracy differs between two benchmarks, call the result a tradeoff at the reported accuracies; do not describe it as an equal-quality comparison.

    ★ A better prompt changes the task presentation; model scale changes the model

    A prompt is the input instruction and context given to a language model. Zero-shot prompting gives no worked demonstrations. Few-shot prompting supplies a few examples. Chain-of-thought prompting supplies or requests intermediate reasoning steps, rather than only a final answer. These distinctions describe the input presented to the model. They do not, by themselves, change its stored parameter count. [Review pp. 27–29]

    Imagine a student who already owns a textbook. Giving the student a worked example changes how the assignment is introduced; it does not add pages to that textbook. Likewise, a reasoning prompt can affect what a model generates and how much generation it performs, while the stored model weights remain the same. More generated steps may require extra runtime; they are not automatically free or correct.

    Model scale here means model size, illustrated in the review by parameter counts. The starred plot associates some larger models with better results on the illustrated reasoning task. It does not establish that every larger model is always more accurate or that every reasoning trace is valid. Discuss the task and the observed comparison, not a universal law inferred from one plot.

    Practice 2 — One prompt gives three solved examples. Another says “show the intermediate steps.” Does either instruction make the stored network larger?
    1. Three demonstrations make the first prompt few-shot. Requesting intermediate steps makes the second a chain-of-thought-style instruction. A prompt can contain both features.
    2. Neither instruction adds learned coefficients to a fixed model. Its parameter count remains unchanged.
    3. The generated sequence can become longer, and answer quality may change. Those are separate questions from stored model size.

    ★ Width and depth describe different ways to make a network larger

    Depth describes how many successive layers the signal passes through. Width describes how many hidden features or neurons a layer has; in a convolution, channel count is a useful width measure. A hidden layer sits between the input and final output. Use the course diagram's counting convention when stating a numerical depth, since conventions can include or exclude the input. [Review p. 30]

    Picture a workshop. More production stations in sequence correspond to more depth. More parallel workbenches at one station correspond to more width. Both can increase capacity and cost, but they change different dimensions. A larger batch means more items visiting the same workshop; it does not add stations or workbenches to the architecture.

    Practice 3 — A network's hidden layers have widths 12 and 12. Design X changes them to 24 and 24. Design Y adds another width-12 hidden layer. Classify the changes.
    1. X increases hidden-layer width from 12 to 24 while retaining two hidden layers.
    2. Y increases hidden depth from two layers to three while retaining width 12.
    3. Both can change weight count and computation. A batch-size change would instead reuse the existing architecture on more examples. Do not call all three changes “more neurons” without identifying their different roles.

    ★ Pruning an entry and removing a channel are physically different operations

    Pruning removes selected parts of a network while trying to preserve useful predictions. Granularity is the size and organization of the unit removed. Unstructured pruning chooses individual weight entries. Structured pruning removes organized units, such as whole channels. The review contrasts the flexible choice of individual entries with the easier dense execution of smaller structured tensors. [Review pp. 62–68]

    A spreadsheet is a useful mental model. Turning scattered cells into zeros leaves the sheet's row and column dimensions intact. Deleting an entire row makes the sheet shorter. Likewise, a mask marks selected coefficients as zero without necessarily reducing their storage allocation or the dense loop that processes them. Sparsity is the fraction of entries that are zero. A sparse pattern may need a special representation and execution method before it produces a speedup.

    Removing an output channel means removing an entire produced feature map and its filter. If the next layer consumes that feature map, its corresponding input channel must also disappear. Otherwise the two layers' shapes disagree. Channel pruning therefore changes both sides of a connection, not merely the selected layer in isolation.

    Practice 4 — Constructed: a 3×3 conv A has 6 inputs and 10 outputs. Conv B has 10 inputs and 14 outputs. Remove two of A's output channels physically. How many weights disappear?
    1. A starts with 10×6×9=540 weights. It keeps 8 output channels, so it becomes 8×6×9=432; saving 108.
    2. B must keep only the same 8 input channels. Its weights fall from 14×10×9=1,260 to 14×8×9=1,008; saving 252.
    3. Together, weights fall from 1,800 to 1,440. The saving is 360 weights, or 20%. Biases are excluded. This is a weight-count result; timing still requires measurement.

    Exam recipe: identify the removed unit; distinguish a zero mask from physically rebuilt dimensions; then follow the changed channel into the next layer. The review's N:M description uses N pruned entries in each group of M. Declare that convention before interpreting a non-half pattern; some other sources use N for retained entries.

    ★ A pruning criterion is a ranking rule, not a guarantee about loss

    A criterion is the rule used to decide which candidate to remove. The starred slides present three signals: weight magnitude, channel scaling factors, and how often activation outputs are zero. Each asks a different question about a different unit. Do not transfer the direction of one ranking to another without checking its meaning. [Review pp. 69–72]

    Magnitude means distance from zero: the absolute value |w|. A negative coefficient can have a large magnitude. Magnitude pruning removes the smallest |w| first. The intuition is that a tiny coefficient often contributes less to a weighted sum, but this is a heuristic, a useful selection rule that does not prove an exact loss change. A tiny coefficient multiplied by a huge input can still matter.

    Practice 5 — Constructed: weights [−0.6, 0.45, −0.015, 0.09]. Remove two by magnitude. Explain why the most negative entry survives.
    1. Take absolute values: [0.6,0.45,0.015,0.09].
    2. The two smallest are 0.015 and 0.09, so remove −0.015 and 0.09.
    3. The most negative entry, −0.6, survives because its magnitude is 0.6, the largest. Signed value and distance from zero are different rankings.

    Scaling-based pruning associates a learned multiplicative number with a filter's output. Multiplying a whole channel by a near-zero scale makes that channel's scaled output small, so the method considers removing the channel. For signed scale values, compare absolute magnitudes. A coefficient-level magnitude question removes entries; a scale question removes a filter or channel.

    Practice 6 — Constructed: four channel scales are [0.7, −0.025, 0.18, −0.5]. Choose one channel by smallest absolute scale.
    1. The magnitudes are [0.7,0.025,0.18,0.5].
    2. Channel 2, scale −0.025, has the smallest magnitude. Select its entire channel, not just one weight inside it.
    3. If the channel is physically removed, update the next layer's input connections and evaluate accuracy. A near-zero scale is evidence used by the criterion, not proof that every prediction is unchanged.

    Average Percentage of Zeros (APoZ) measures how often a neuron's observed output equals zero. An activation is a runtime feature value; ReLU turns negative inputs into zero. APoZ=zero outputs/observed outputs, or that fraction multiplied by 100 for a percentage. A high-APoZ channel is inactive more often and is a removal candidate. This ranking direction is the opposite of “remove the smallest APoZ”: the source says smaller APoZ suggests greater importance.

    Practice 7 — Constructed: channel A has 10 zeros among 16 observations; B has 4 zeros among 16. Which is selected by APoZ, and what could the sample miss?
    1. A: 10/16=62.5%. B: 4/16=25%.
    2. A is zero more often, so it is the first removal candidate under this heuristic.
    3. The observed examples may miss rare inputs on which A is useful. Frequency of inactivity is not a complete measure of how important the occasional nonzero output is.

    ★ Test each layer's tolerance, then remember that layers interact

    A pruning ratio is the fraction of weights removed from a specified population. Layer sensitivity means how strongly task quality changes when that layer is pruned. The review tests one layer at several ratios, measures accuracy, and repeats for other layers. An accuracy threshold is the minimum acceptable value. A sensitive layer crosses that threshold early; a less sensitive layer tolerates a larger ratio. [Review pp. 73–78]

    Think of shortening several paragraphs in an explanation. One paragraph may contain repetition, while another contains the only definition the reader needs. Removing the same percentage from both is not necessarily sensible. But independently shortening each paragraph does not prove the whole explanation remains understandable; removing repetition in one place can make another sentence newly important.

    Practice 8 — Constructed: at rates 0%,25%,50%,75%, layer A gives accuracy [94,93,89,80], and B gives [94,94,92,87]. Minimum accuracy is 92%. Pick each largest tested allowed rate.
    1. A allows 0% and 25%; 50% fails because 89<92. Its largest allowed tested rate is 25%.
    2. B allows 0%,25%,50%; 75% fails because 87<92. Its largest is 50%. Equality counts as meeting this threshold.
    3. These are isolated layer tests. Evaluate the combined pruned network before promising accuracy≥92%, because removing one layer's features changes the next layer's input.

    To find whole-model sparsity, count removed weights rather than averaging layer percentages. With original layer counts Nₗ and original-count rates rₗ, global sparsity is ΣNₗrₗ/ΣNₗ. Bigger layers carry bigger weight in this average. Always state whether the denominator is the original population or the current survivors.

    Practice 9 — Constructed: layer A has 240 weights at 25% pruning; B has 360 at 50%. Find total sparsity.
    1. A removes 240×0.25=60. B removes 360×0.50=180.
    2. Total removed=240 from 600, so global sparsity=40%.
    3. The unweighted average 37.5% would be wrong because the layer counts differ. This calculation measures counts; it does not supply the jointly pruned model's accuracy.

    ★ AMC searches for ratios; an importance score chooses what to remove

    AutoML for Model Compression (AMC) formulates compression as a reinforcement-learning problem. In this kind of search, an agent observes a state, chooses an action, and receives a reward evaluating its decision. Here the state describes model/layer context, the action selects a compression choice, and the reward reflects the optimization objective. The review depicts an actor choosing actions and a critic providing evaluation. [Review pp. 79–80]

    This is a different level of decision from “remove the smallest weight.” A ratio search asks how much capacity each layer should lose. A magnitude criterion asks which entries to remove for a chosen amount. NetAdapt is described as a rule-based progressive method for adapting per-layer choices to a global resource constraint, such as device latency. Fine-tuning means updating the surviving learned weights after changing the model. These categories can work together without becoming interchangeable names.

    Practice 10 — A policy sees layer information, chooses a compression ratio, and receives a quality/resource reward. Which review method matches? Does the description specify magnitude pruning?
    1. The state–action–reward formulation matches AMC.
    2. It does not specify which individual weights are ranked; that is a separate criterion decision. Magnitude, scale, and APoZ identify different removal signals.
    3. If the comparison reports different accuracies, describe a resource–quality tradeoff. An attractive smaller-model bar does not automatically prove equal-quality superiority.

    ★ Repeated pruning works on a smaller population each time

    Iterative pruning removes capacity in several stages, typically with fine-tuning between stages. The mental model is a careful haircut with opportunities to adjust, rather than one enormous cut. The source illustrates better recovery for iterative pruning and fine-tuning in its example; it does not promise that any target sparsity is safe. [Review p. 82]

    If a round removes fraction r of current survivors, it keeps fraction 1−r. Starting with N₀, k equal rounds leave N₀(1−r)ᵏ; original-count sparsity is 1−(1−r)ᵏ. If the question instead specifies original-count target sparsities, follow those targets directly. The denominator is part of the problem, not a formatting detail.

    Practice 11 — Constructed: start with 1,200 weights, remove 25% of survivors, fine-tune, then remove 20% of survivors. Find final count and sparsity.
    1. First round keeps 1,200×0.75=900.
    2. Second round keeps 900×0.80=720.
    3. Total removed=480, so original-count sparsity=480/1,200=40%. Adding 25%+20%=45% ignores the smaller second-round denominator.
    Practice 12 — Constructed: from 1,200 weights, set original-count sparsity targets of 25% then 45%. How does that differ from Practice 11?
    1. The first target retains 1,200×0.75=900.
    2. The second retains 1,200×0.55=660. Moving between the targets removes 240 of the 900 survivors, a survivor-based rate of 26⅔%.
    3. The result differs from the 720 survivors in Practice 11 because “20% more of current survivors” and “raise the original-count target by 20 percentage points” are different instructions.

    Exam recipe: identify the denominator, compute each survivor count, calculate the final fraction relative to the original, and explain what fine-tuning can repair. Avoid treating arithmetic sparsity as an accuracy guarantee or an automatic device speedup.

    Fewer bits make each stored weight and activation smaller

    A convolution gives you two counts: how many learned weights exist, and how many activation values the layer produces. A number format answers the next question: how much space does each value occupy? If a layer stores 864 weights, 32-bit values need 864 × 32 / 8 = 3,456 bytes. Eight-bit values need 864 bytes. The weight count remains 864; the bytes per weight change. This is a constructed storage example, assuming packed values and excluding metadata.

    The same reasoning applies to an activation map. A constructed output with 16 channels and a 32 × 32 spatial grid contains 16 × 32 × 32 = 16,384 values per image. At 32 bits each, that is 65,536 bytes; at 8 bits, 16,384 bytes. Fewer bits can save memory even when the convolution’s output shape and MAC count stay the same. Whether the implementation runs faster is a separate hardware question.

    The review’s new number-format material explains what those smaller stored values actually mean. We start with ordinary binary counting, then add signs, fractions, and exponents. The starred tasks emphasize interpreting codes, encoding FP32, handling zero and special values, and explaining range versus precision. [Review, pages 83–90] [Review, pages 91–98]

    Binary powers are just the column values in a different counting system

    In decimal, the columns in 231 mean hundreds, tens, and ones. In binary, the columns are powers of two: …, 16, 8, 4, 2, 1. Each column contains either 0 or 1. So binary 1010 is 1 × 8 + 0 × 4 + 1 × 2 + 0 × 1 = 10. The notation 2³ means 2 × 2 × 2 = 8; the superscript is an exponent, the number of repeated factors.

    Negative powers describe fractions: 2⁻¹ = 1/2; 2⁻² = 1/4; 2⁻³ = 1/8. Binary 0.101 therefore means 1/2 + 0/4 + 1/8 = 0.625. These are the same place values that will appear in a floating-point fraction.

    Eight unsigned bits use column values 128, 64, 32, 16, 8, 4, 2, 1. The source’s 11000000 is 128 + 64 = 192 if unsigned. “Unsigned” means the format does not encode negative values. But the same bits can mean −64 under two different signed schemes. [Review, pages 83–84]

    For sign-magnitude, the first bit selects the sign, and the remaining bits give the magnitude. For two’s complement, the first column has value −128 instead of +128; the others retain their positive values. The review’s “signed” branch is sign-magnitude, as its preceding page explicitly specifies. These schemes happen to agree on 11000000, but are not interchangeable.

    Practice 1 · Read one fresh bit pattern three ways

    Constructed question: Decode 10011010 as unsigned, sign-magnitude, and two’s complement.

    Worked answer: The nonzero unsigned columns are 128, 16, 8, and 2: sum = 154. In sign-magnitude, the first bit supplies minus and the remaining magnitude is 16 + 8 + 2 = 26: −26. In two’s complement, the top column contributes −128: −128 + 16 + 8 + 2 = −102. A quick check is unsigned 154 − 256 = −102. State the scheme before the answer.

    Fixed point assigns the same fractional scale to every stored value

    Take the source’s eight-bit 00110001. Its integer value is 32 + 16 + 1 = 49. If four bits are fractional, interpret it as 0011.0001. This is 2 + 1 + 1/16 = 3.0625. Equivalently, divide the stored integer 49 by 16. The point’s location is agreed in advance; it is not a separately stored bit. [Review, page 85]

    With four fractional bits, increasing the stored integer by one increases the represented value by 1/16 = 0.0625. That is the format’s spacing. Two’s-complement signs still apply: decode the integer first, then divide by 16. In this eight-bit convention, the real range is −128/16 = −8 through 127/16 = 7.9375.

    Practice 2 · Read a fresh fixed-point value

    Constructed question: With eight total bits, two’s complement, and four fractional bits, decode 11100110.

    Worked answer: Unsigned value = 128 + 64 + 32 + 4 + 2 = 230. The first bit is 1, so the signed integer is 230 − 256 = −26. Now apply the fractional scale: −26/16 = −1.625. Do not merely put a minus sign before the unsigned value; that would be a different signed representation.

    Floating point gives each value its own power-of-two scale

    A normal floating-point number has three fields: sign, exponent, and fraction. Think “sign × a number between 1 and 2 × a power of two.” For example, 6.5 is binary 110.1. Moving the point gives 1.101 × 2². The leading part is 1 + 1/2 + 1/8 = 1.625; multiply by 4 to recover 6.5.

    The exponent tells us how far the binary point moves. Its stored field uses a bias, a fixed offset, so a nonnegative field can encode negative exponents. FP32 uses 8 exponent bits and bias 127. A real exponent −2 is stored as 125 because −2 + 127 = 125; decoding subtracts 127. The sign uses 1 bit and the fraction uses 23 bits. [Review, pages 86–87]

    The initial 1 of a normal binary significand is implicit: it is understood without being stored. The fraction field stores only the digits after the point. Thus 1.100 has fraction 1/2 and significand 1.5. A fraction field beginning 100 is not the decimal integer 100.

    The source encodes 0.265625 = 17/64. Binary 0.010001 becomes 1.0001 × 2⁻². Sign 0; stored exponent 125 = 01111101; stored fraction begins 0001, representing 1/16. Reverse check: (1 + 1/16) × 1/4 = 17/64 = 0.265625.

    Practice 3 · Encode a fresh FP32 number

    Constructed question: Encode 0.375 exactly in FP32. Give sign, stored exponent, fraction field, and a reverse check.

    Worked answer: 0.375 = 1/4 + 1/8 = binary 0.011 = 1.1 × 2⁻². Sign is 0. Stored exponent is −2 + 127 = 125 = 01111101. Drop the leading 1: the fraction is 10000000000000000000000, meaning 1/2. Fields are 0 | 01111101 | 10000000000000000000000. Decode: (1 + 1/2) × 1/4 = 0.375. This value fits exactly, so no rounding rule is needed.

    FP16 uses the same normal-number reasoning but 5 exponent bits,10 fraction bits, and bias 15. The source’s fields 1 | 10001 | 1100000000 mean sign negative, exponent 17−15 = 2, fraction 1/2+1/4 = 0.75: −1.75 ×4 = −7. [Review, pages 94–95]

    Practice 4 · Decode a fresh FP16 number

    Constructed question: Decode 0 | 10001 | 0010000000.

    Worked answer: Sign 0 means positive. Exponent 10001 is 17; subtract the FP16 bias 15 to get 2, so multiply by 4. Fraction 001 contributes 1/8 = 0.125. Add the normal hidden 1: 1.125. Thus 1.125 ×4 = 4.5. Using bias 127 or forgetting the hidden 1 would answer a different problem.

    Zero needs a special branch because a hidden leading one cannot equal zero

    If every value had a significand at least 1, multiplying by a power of two could never make zero. IEEE formats therefore treat an all-zero exponent field differently. Remove the hidden 1 and use the smallest normal scale. Zero fraction then gives signed zero; nonzero fraction gives a subnormal, a tiny value below the normal range. [Review, pages 88–90]

    For FP32, the smallest normal scale is 2⁻¹²⁶. Its 23 fraction bits make the smallest subnormal one step of 2⁻²³ times that scale, hence 2⁻¹⁴⁹. The largest subnormal is (1−2⁻²³) ×2⁻¹²⁶, exactly one 2⁻¹⁴⁹ step below the smallest normal. These powers are easier to understand after a tiny model.

    Practice 5 · Understand subnormals with a small model

    Constructed teaching model: Assume 3 exponent bits,2 fraction bits, bias 3, and IEEE-style zero/subnormal rules. Find the smallest normal, smallest subnormal, and largest subnormal.

    Worked answer: Smallest normal uses stored exponent 1: real exponent 1−3 = −2, giving 1/4. With 2 fraction bits, subnormal fractions are 1/4,2/4,3/4. Multiply these by the fixed 1/4 scale: the positive subnormals are 1/16,2/16,3/16. Thus smallest is 0.0625, largest 0.1875, and smallest normal 0.25. The final gap is 1/16, one step. This miniature format teaches the mechanism; it is not an additional source format.

    All-one exponents are another decision branch

    For IEEE FP32/FP16, an all-one exponent and zero fraction means infinity; a nonzero fraction means NaN, “not a number.” The sign distinguishes positive and negative infinity. Do not insert these fields into the normal-value formula. The source’s table separates zero, subnormal, normal, and special branches. [Review, pages 92–93]

    Practice 6 · Classify before calculating

    Constructed question: Classify these FP16 fields: A1|00000|0000000000; B0|00000|0000000001; C1|11111|0000000000; D0|11111|0000000010.

    Worked answer: A is negative zero. B is the smallest positive subnormal,2⁻²⁴. C is negative infinity. D is NaN because the all-one exponent has a nonzero fraction. Branch choice comes first; only a normal or subnormal branch proceeds to finite-value arithmetic.

    Range and precision ask different questions

    Range asks how small and large the format can reach. Precision asks how finely it distinguishes nearby values at a given scale. More exponent bits usually buy more reachable scales; more fraction bits buy smaller steps within a scale. At values between 1 and 2, FP16’s 10 fraction bits give step 1/1024; BF16’s 7 fraction bits give step 1/128. BF16 has more exponent bits, but its nearby-value step here is eight times larger. [Review, page 94]

    The source’s starred FP4 comparison makes the tradeoff visible with tiny codebooks. E1M2 allocates 1 exponent and 2 fraction bits after the sign: its nonnegative values are 0,0.5,1,1.5,2,2.5,3,3.5. E3M0 allocates 3 exponent and no fraction bits: 0,0.25,0.5,1,2,4,8,16. It reaches farther but leaves larger gaps at high magnitudes. These source FP4 conventions do not reserve IEEE-style infinities/NaNs. [Review, page 97]

    Practice 7 · Explain a range/precision tradeoff with actual values

    Constructed question: For the two source codebooks above, which represents 8 exactly? Which represents 2.5 exactly? Which gives a nearer value to 2.9 under nearest rounding?

    Worked answer: E3M0 represents 8; E1M2 represents 2.5. At 2.9, E1M2 chooses 3, distance 0.1. E3M0 chooses 2, distance 0.9; 4 is farther away at 1.1. E1M2 is closer for this input, but cannot reach 8. One example’s smaller error does not establish the best format for every tensor.

    The source’s FP8 examples also have their own contracts: E4M3 reaches 448 and has no infinity encoding, while E5M2 reaches 57344 and reserves infinity/NaN patterns. Their field widths alone do not justify copying every FP32 special-case rule. Consult the named format’s convention. [Review, page 96]

    Quantization replaces a large set of possible values with a discrete codebook

    The final source page calls the difference between an input and its quantized value quantization error. For intuition, take a constructed grid with spacing 0.5: …,−0.5,0,0.5,1,1.5,… . Under nearest rounding, input 1.1 becomes 1, with signed reconstruction error 1−1.1 = −0.1. Storage saves space because you store a small code identifying a permitted value rather than an unrestricted high-precision input. [Review, page 98]

    Practice 8 · Connect the codebook to CNN storage

    Constructed question: A tensor has 864 weights. Compare ideal packed FP32 and 4-bit storage. Then suppose a stated quantizer rounds its weight 1.1 to 1. What is the signed error, and does the storage ratio prove an equal speedup?

    Worked answer: FP32 stores 864 ×32/8 = 3,456 bytes. Four-bit packing stores 864 ×4/8 = 432 bytes, an 8-fold raw-value storage reduction. The signed error is −0.1. This assumes packing and excludes scales/metadata. It establishes neither measured speed nor final model accuracy; hardware execution and how the model reacts to changed weights still matter.

Before moving on, you should be able to say which representation branch you chose, what each field contributes, and how to decode your final bits back into a real value.

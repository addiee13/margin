Inside a Neural Network: Layers, Channels, and What They Cost

A neural network is a stack of a few repeating building blocks: fully-connected layers, convolutions, pooling, normalization and activations. This page explains what each block computes and what its tensors look like. It spends extra time on the idea everything later depends on, the channel. Then it shows how to measure what a network costs in parameters, memory, latency and energy, which is the foundation for pruning and the rest of the course.

1 · Efficiency matters because models outgrew their hardware

Deep learning is everywhere: vision, language, code generation, multimodal models and robots. Large language models even show emergent behaviors such as few-shot learning and chain-of-thought reasoning, but at the cost of enormous model size. The course goal is doing more with less: making AI fast, small and everywhere. [L2, motivation]

The numbers show why. AWQ, a quantization method, speeds LLaMA-2-7B from 50 to 166 tokens/s on an RTX 4090, about 3.3× [AWQ, §5]. A robotics transformer runs at only 3 Hz because of its compute cost and network latency. Running models on the edge (phones, laptops, cars, robots) also keeps personal data private and works without internet. Edge hardware such as the Qualcomm Hexagon DSP, the Apple Neural Engine, NVIDIA Jetson and microcontrollers still has a huge gap to cloud processors. Efficiency rests on three pillars: algorithms, systems and hardware, each of which must support tricks like pruning and quantization. [L2, Three pillars]

2 · The vocabulary: synapses carry weights, neurons carry activations

In the slides' 3-layer network (2 hidden layers), each connection is a synapse, also called a weight or parameter. Each circle is a neuron, also called a feature or activation. A neuron takes inputs xi, multiplies each by its weight wi, adds a bias b, and passes the sum through an activation function f: [L3, Recap DNN]

y = f( Σi wixi + b )

WordSame thing asIs it learned?
Synapseweight, parameterYes, stored in the model file
Neuronfeature, activationNo, computed fresh for every input
Widthsize of the hidden layersA design choice

Keep this split in mind: weights are what the model is, and activations are what it produces while running. Section 7 shows that these two cost memory in very different ways.

3 · A fully-connected layer is one matrix multiply

Every output neuron connects to every input neuron. The slides' intuition: think of x as 5 features of a person (height, weight, age…). To score "fits a basketball team," you weight each feature by how much it matters, add them up, and shift by a bias: [L2–3, One neuron]

y0 = w00x0 + w01x1 + w02x2 + w03x3 + w04x4 + b0  →  yi = Σj wijxj + bi

Stack all the output neurons and the whole layer collapses into Y = XWT + b: one matrix multiply, plus a bias.

TensorShapeMeaning
Input X(n, ci)n samples in the batch, ci input channels (features)
Output Y(n, co)co output channels
Weights W(co, ci)one row per output neuron
Bias b(co,)one per output neuron

Notice the word channels already: in a linear layer, a "channel" is simply one feature. For a single sample, the shapes are (1, ci) and (1, co). Stacking two such layers gives a multilayer perceptron (MLP). Each output neuron does ci multiply-accumulates (MACs), so the layer does ci·co MACs. [L4, #MACs]

4 · A channel is one "view" of the input, and every filter makes one

Here is the idea that the pruning lectures assume you know. Start with a color photo. It is not one grid of numbers but three: a red grid, a green grid and a blue grid stacked on top of each other. Each of those grids is a channel. An RGB image has ci = 3 channels, each h × w pixels. [L3, 2D conv, RGB split]

A convolution slides a small kernel (for example 3×3) over the image and computes a weighted sum at every location. The kernel decides what you see. The same photo with four different 3×3 kernels gives four different results: [L3, The kernel decides]

Now the key step. A conv layer does not learn one kernel; it learns many filters, and each filter outputs its own channel. In the slides, a 3-channel cat photo goes through N learned filters and comes out as N output maps. One map highlights edges, another fur texture, another outlines. Those output maps are the layer's output channels, also called feature maps. [L3, One filter, one feature map]

Since the input has ci channels, each filter is really a stack of ci kernels, one per input channel. The filter applies each kernel to its channel and adds the results into a single output map. That is why the weight tensor has the shape

W : (co, ci, kh, kw)

with one k×k kernel for every (output channel, input channel) pair. In the slide, ci = 3 (RGB) and co = N, the number of learned filters. [L3, Weight tensor shape]

Why channels are the natural unit for pruning

Deleting output channel j of a layer removes three things at once:

  1. Filter j in this layer: ci·kh·kw weights.
  2. Feature map j: ho·wo activations that no longer need to be computed or stored.
  3. The matching slice of every filter in the next layer. That layer's input now has one channel fewer, so each of its filters loses one k×k kernel.

What is left is an ordinary, smaller dense convolution, so every library and chip runs it faster with no special support. That is the "direct speedup" in the pruning slides. Fine-grained pruning, by contrast, leaves scattered zeros inside a tensor of the same shape. Try it:

Lab 2 · Prune channels between two conv layers (56×56 maps, 3×3 kernels)
Layer A: 64 → 128 channels  ·  Layer B: 128 → 256 channels

Drag the slider to keep 64 of the 128 middle channels. Layer A's weights halve, the feature maps between the layers halve, and Layer B's weights also halve, even though you never touched Layer B's own output. One decision saves memory in two layers. It also explains the pruning lecture's warning that channel pruning has a smaller compression ratio: you can only remove whole channels, never the single weakest weights.

5 · Convolution variants: same idea, different shapes

In a conv layer, each output neuron connects only to the input neurons in its receptive field, not to everything. In 1D convolution the kernel slides along one dimension, such as time in an ECG signal, and learns temporal patterns. In 2D convolution it slides along height and width, such as detecting a stop sign in a street scene, and learns spatial patterns like edges, textures and shapes. [L3, 1D vs 2D]

TensorLinear1D conv2D conv
Input X(n, ci)(n, ci, wi)(n, ci, hi, wi)
Output Y(n, co)(n, co, wo)(n, co, ho, wo)
Weights W(co, ci)(co, ci, kw)(co, ci, kh, kw)
Bias b(co,)(co,)(co,)

Notation: n batch size · ci/co input/output channels · h, w height/width · kh, kw kernel height/width · g groups.

Stride is how far the kernel jumps between positions. On the slide's 7×7 input with a 3×3 kernel, stride 1 visits all 25 positions (a 5×5 output), while stride 2 visits only 9 (a 3×3 output). The slides don't give a general formula, but the standard one, with padding p zeros added around the border, is: [Dumoulin & Visin, §2]

ho = ⌊(hi + 2p − kh) / s⌋ + 1

Check it against AlexNet's first layer (224 input, 11×11 kernel, stride 4, pad 2): ⌊(224 + 4 − 11)/4⌋ + 1 = 55. That matches the 96×55×55 output in the slides.

Grouped convolution splits the channels into g groups, and each group is a narrower convolution that sees only its own ci/g input channels. The weights shrink from (co, ci, kh, kw) to (g·co/g, ci/g, kh, kw), which is g times fewer. Depthwise convolution is the extreme case g = ci = co. Every channel gets its own independent filter and channels never mix, so W is just (c, kh, kw). Efficient mobile networks like MobileNetV2 are built on this. [MobileNetV2, §3.1]

6 · The supporting layers have few or no parameters

Pooling downsamples a feature map. Each output neuron pools the features in its receptive field, like convolution, and the stride usually equals the kernel size (s = k). Pooling works on each channel independently and has no learnable parameters. [L3, Pooling]

Normalization makes optimization faster. Each feature is shifted and scaled using the mean μi and standard deviation σi over a set of pixels Si: [Wu & He, §3.1]

x̂i = (xi − μi) / σi,   μi = (1/m) Σk∈Si xk,   σi = √( (1/m) Σk∈Si (xk − μi)² + ε )

Then a per-channel linear transform with a trainable scale γ and shift β, yi = γ x̂i + β, restores the representational ability that normalization might remove. The variants differ only in which set Si they average over:

VariantStatistics computed over
Batch NormOne channel, across the whole batch and all pixels
Layer NormOne sample, across all channels and pixels
Instance NormOne sample, one channel
Group NormOne sample, one group of channels

Look back at the pruning page: scaling-based pruning reuses exactly this per-channel γ. A channel with a tiny γ is barely let through, so it can be cut.

Activation functions are typically non-linear, and most common activation functions have no learnable parameters. [L3, Activation]

NameFormula
Sigmoidy = 1/(1 + e−x)
ReLUy = max(0, x)
ReLU6y = min(max(0, x), 6)
Leaky ReLUy = max(αx, x)
Swishy = x/(1 + e−x)
Hard Swish0 if x ≤ −3; x if x ≥ 3; x(x + 3)/6 otherwise

Others include Tanh, GELU, ELU and Mish. ReLU's flat zero region is what creates the zeros that APoZ pruning counts.

Putting it together. The slides' CNN example (VGG-style) shrinks space while growing channels: 224×224×64 → 112×112×128 → 56×56×256 → 28×28×512 → 14×14×512 → 7×7×512, then fully-connected layers of 4096, 4096 and 1000. Each stage is conv + ReLU, with max pooling between stages. [Simonyan & Zisserman, Table 1]

7 · Efficiency has more than one meaning

The slides draw a triangle. Storage makes models smaller, latency makes them faster, and energy makes them greener, and both computation and memory sit in the middle and drive all three. The metrics come in two families: [L3, Efficiency metrics]

Memory-relatedComputation-related
#parameters · model size · total / peak #activationsMAC · FLOP, FLOPS · OP, OPS

Latency and throughput are not the same

Latency is the delay for one task. For example, SegFormer takes 638 ms per frame (82.4 mIoU), while EfficientViT takes 46 ms (82.7 mIoU). Throughput is the rate at which data is processed, for example 6.1 vs 77.4 videos per second. [L3, Latency, Throughput]

Puzzle from the slidesDesign 1 handles one image at a time in 50 ms. Design 2 handles 4 images in parallel, taking 100 ms each. Which has lower latency? Which has higher throughput?
Answer

Design 1 has 50 ms latency and 20 images/s throughput. Design 2 has 100 ms latency but 40 images/s throughput. Higher throughput does not imply lower latency, and lower latency does not imply higher throughput. Parallelism buys throughput; making each job faster buys latency.

Latency is roughly set by whichever is slower, computing or moving data:

Latency ≈ max(Tcomputation, Tmemory)

Term≈ NN specification÷ hardware specification
Tcomputation#operations in the model#operations the processor does per second
Tdata movement of weightsmodel sizememory bandwidth
Tdata movement of activationsinput + output activation sizememory bandwidth

where Tmemory ≈ Tactivations + Tweights. Every term is a model number divided by a hardware number. You can make a model faster by shrinking the top line, which is what pruning does, or by buying a better bottom line.

Energy: moving data is what costs

Rough energy per operation at 45 nm, 0.9 V. Each bar's length is on a log scale: [Horowitz, Fig. 1.1.9]

A single DRAM access costs about 200× a 32-bit multiply. Data movement means more memory references, and that means more energy. This is why the pruning lectures care about removing activations, not just multiplies.

Counting parameters

#Parameters is the number of elements in the weight tensors. Ignoring bias: [L3, #Parameters]

Model size is the storage for the weights. When the whole network uses one data type, model size = #parameters × bit width. For AlexNet's 61M parameters, 32-bit floats take 61M × 4 bytes ≈ 244 MB, and 8-bit integers take 61M × 1 byte = 61 MB. That 4× saving is the promise of quantization.

The totals are about 61M parameters and 932,264 activations. Now look at where each one sits. The three linear layers hold 58.6M of the 61M parameters (about 96%), yet produce only 9,192 activations. The first conv layer has just 34,848 parameters but produces the most activations of any layer. Weights pile up at the end of a CNN, and activations pile up at the start. The peak activation memory is roughly the largest input + output pair: 150,528 + 290,400 = 440,928. [L3, AlexNet #Activations]

Activations, not parameters, are often the real bottleneck

  • Inference (int8): at about 70% ImageNet top-1, MobileNetV2-0.75 has 4.6× fewer parameters than ResNet-18, but a 1.8× higher peak activation. [MCUNet, Fig. 2]
  • Imbalance: MobileNetV2's memory peaks at 1,372 kB in block 2, far above a 256 kB microcontroller limit, while later blocks need little.
  • Training (fp32): MobileNetV2-1.4 has 4.3× fewer parameters than ResNet-50 (102 MB), but its activations shrink only 1.1×. ResNet-50's activations (707 MB) are about 7× larger than its parameters. [TinyTL, Fig. 1]
  • Per layer: early layers have high activation memory, and late layers have high weight memory. It is the same pattern you just found in AlexNet.

Exam check: try before you open

  1. A conv layer has 32 input channels, 64 output channels and 3×3 kernels. Write W's shape and count the parameters.
    Answer

    W : (64, 32, 3, 3), so 64·32·9 = 18,432 parameters (plus 64 biases).

  2. The same layer with g = 4 groups. And as depthwise (assume ci = co = 32)?
    Answer

    Grouped: 18,432/4 = 4,608. Depthwise: 32·9 = 288.

  3. Input 3×32×32, 5×5 conv, stride 1, padding 0, 16 filters. What is the output shape?
    Answer

    (32 − 5)/1 + 1 = 28, so the output is 16×28×28. The output channel count always equals the number of filters.

  4. A model has 25M parameters. What is its model size in fp32 and in int8?
    Answer

    fp32: 25M × 4 B = 100 MB. int8: 25 MB.

  5. Why can't you judge a CNN's memory needs from #parameters alone?
    Answer

    Activations often dominate, especially in early layers and during training. Example: MobileNetV2 has 4.6× fewer parameters than ResNet-18 but a 1.8× higher peak activation.

  6. Does pooling add parameters? Does ReLU? Does BatchNorm?
    Answer

    Pooling has none. ReLU has none. BatchNorm has two per channel, the trainable γ and β.

  7. If you prune 25% of the output channels of layer L, which other layer's weights shrink, and by how much?
    Answer

    Layer L+1. Its input channels drop by 25%, so its weights shrink by 25% too. Layer L's own weights also drop by 25%, along with the feature maps between the two layers.

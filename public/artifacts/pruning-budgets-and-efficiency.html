Pruning Budgets Become Useful Only When You Count the Right Resource

A sparsity percentage tells you how many weights were removed. It does not by itself tell you the saved bytes, the new tensor shapes, the latency, or whether accuracy will recover. This page works through the calculations behind the final pruning review.

1 · Sparsity, density, and compression have different denominators

Start with a constructed model containing 1,000,000 scalar weights. Keeping 200,000 means density d = 200,000 / 1,000,000 = 0.20 and sparsity s = 1 − d = 0.80. The parameter compression factor is 1,000,000 / 200,000 = 5×. Thus “80% pruned,” “20% density,” and “5× fewer nonzero weights” describe the same count. Sparsity is the fraction removed; density is the fraction retained. The lecture's density plot explicitly divides nonzero weights by total weights. [Lecture6, slide 40]

s = 1 − K/P; d = K/P; Cparameters = P/K = 1/(1 − s)

Here P is the original number of weights and K the surviving number. A budget ‖WP‖0 ≤ N allows at most N nonzero weights, including exactly N. With P = 100 and N = 30, any feasible model has sparsity at least 70%; it need not use every available nonzero. This inclusive boundary matches the final review, whereas the older companion page prints a strict < in its objective. [Lecture6, slide 56]

Per-layer sparsities cannot normally be averaged equally. In a constructed two-layer network, layer A contains 100 weights and layer B contains 900. Prune 10% of A and 80% of B: remove 10 + 720 = 730 of 1,000 weights, for 73% global sparsity. The simple mean (10% + 80%)/2 = 45% is wrong because it treats a small layer like a large one.

sglobal = (Σl Plsl)/(Σl Pl)

Always name both the removed unit and the baseline denominator before interpreting a pruning ratio.

2 · Rebuilt channels change shapes and the work of two layers

A multiply-accumulate (MAC) multiplies one weight by one activation and adds the product to an accumulator. A linear layer with ci input features and co outputs uses cico MACs per sample. A grouped convolution uses co(ci/g)khkwhowo MACs, where g is the group count, k kernel size, and ho × wo output size. Bias adds, normalization, and activation operations are excluded here. [Lecture4, slides 19–21]

The convolution formula follows directly: each output scalar requires (ci/g)khkw products, and there are cohowo output scalars. For batch size B, multiply this count by B. Under the lecture's convention, one MAC is two floating-point operations (FLOPs), one multiply and one add. FLOPS, with the final S, means floating-point operations per second, a rate rather than an operation count. [Lecture4, slide 24]

Constructed example: layer A maps 8 channels to 16 through 3×3 kernels; layer B maps those 16 channels to 32 through 3×3 kernels. Both have 10×10 outputs, stride 1, padding 1, and no bias. Remove four of A's sixteen output channels and physically rebuild the tensors. B now has twelve input channels but still thirty-two output channels.

Weight saving = 1,440/5,760 = 25%; MAC saving = 144,000/576,000 = 25%; middle-activation saving = 400/1,600 = 25%. FP32 middle activations save 400·4 = 1,600 bytes. This mechanism follows the lecture's channel/filter granularity: removing one feature map also removes its corresponding inputs to the next convolution. [Lecture6, slides 6–9]

Setting those filters to zero while keeping their original dense shapes is a mask. It represents the same deleted contribution, but a dense implementation can still execute 576,000 MACs and store 1,600 middle activation slots. Real shape reduction removes the slots. Residual additions, concatenations, groups, and depthwise links may force coordinated channel changes; the simple chain above deliberately avoids these constraints.

3 · Sparse metadata can consume the nominal storage saving

Dense weight storage is P·b/8 bytes for b-bit weights. Constructed example: 1,000 FP32 weights occupy 4,000 bytes. At 80% sparsity, 200 nonzeros occupy 800 bytes if values alone are counted. If each also needs a 32-bit flat index, indices add 800 bytes, producing 1,600 bytes before headers and other metadata: 4,000/1,600 = 2.5× storage compression, although the parameter compression is 5×. A dense file with zeros still occupies 4,000 bytes under this format. The course introduces model size as parameter count times bit width; the explicit sparse index accounting here is an original extension. [Lecture4, slide 11]

For N:M sparsity this page uses N retained values in every group of M positions. Some material counts pruned positions instead, so state the convention; 2:4 is symmetric and hides the difference. In a constructed sixteen-value FP16 tensor, four groups of four retain two values each. Dense values occupy 16·16 = 256 bits. Sparse values occupy 8·16 = 128 bits. Each retained value's position among four slots takes two bits, adding 8·2 = 16 bits: 144 bits = 18 bytes versus 32 dense bytes, giving 256/144 ≈ 1.78× compression. The slides illustrate 2:4 and per-value index storage. [Lecture6, slide 7]

There are six unordered ways to choose two positions, since C(4,2) = 6. An ideal fixed-size packed pattern identifier needs ceil(log26) = 3 bits per group. That is different from two 2-bit position indices, which consume 4 bits per group. An ideal format using three group bits would occupy 128 + 4·3 = 140 bits, but that is a mathematical bound for this coding choice, not a claim about a hardware format. Neither representation promises 2× whole-model storage or latency.

4 · Operation savings accelerate only the work they remove

Latency measures time for one task; throughput measures tasks per second. In a constructed serial workload, 50 ms per image gives 1/0.050 = 20 images/s. Processing four images together in 100 ms gives 4/0.100 = 40 images/s, while each image waits 100 ms. Improved throughput can coexist with worse latency. [Lecture3, slides 32–34]

A useful optimistic bound is max(Tcompute, Tmemory) when computation and data transfers overlap. Compute time is operation count divided by sustained compute rate; memory time is transferred bytes divided by sustained bandwidth. In a constructed layer, 432,000 MACs = 864,000 FLOPs. At 100 million FLOPs/s, Tcompute = 8.64 ms. Transferring 1,000,000 bytes at 100 million bytes/s takes 10 ms. The bound is 10 ms. Halving computation to 4.32 ms still leaves that 10 ms memory bound if transfers do not change. Without overlap, the sum would instead be 18.64 ms before the change. [Lecture4, slide 5]

Constructed whole-model bound: if 60% of original latency is accelerated 2× and 40% is unchanged, the new time fraction is 0.60/2 + 0.40 = 0.70. Speedup is 1/0.70 ≈ 1.43×. This accounting, often called Amdahl's law, is an original derivation of the stated assumption. In practice kernel launches, data conversion, batch size, bandwidth, and the sparse kernel implementation also matter. Measure the rebuilt model on the target device.

5 · Ratio search tests feasible accuracy rather than guessing a percentage

Sensitivity analysis prunes one layer at a time over trial ratios and measures accuracy degradation. Its limitation is interaction: isolated layer results do not guarantee that combining the cuts preserves the same accuracy. [Lecture6, slides 29–34]

Constructed case: baseline accuracy is 90%. A two-percentage-point maximum drop requires at least 88%, not “88% of baseline.” Accuracy at sparsities 0%, 25%, 50%, 75% is [90, 89.5, 88, 80]% for A and [90, 90, 89, 88.5]% for B. The largest tested admissible ratios are A = 50%, B = 75%. If A has 100 weights and B 900, their proposed global sparsity is (50 + 675)/1,000 = 72.5%. Test the combined model and fine-tune; isolated feasibility is insufficient. A relative 2% accuracy loss would instead set the threshold to 90%·0.98 = 88.2%.

AMC uses a reinforcement-learning agent to choose continuous per-layer actions. The state describes the layer and the resource history; action is its ratio; reward favors accuracy under a constraint. In the lecture's hard-constraint illustration, invalid candidates receive −∞. For a constructed 50 ms budget, model A at 48 ms with 12% error receives reward −0.12 if error is a fraction; model B at 52 ms with 8% error is infeasible despite better accuracy. [Lecture6, slides 37–39]

NetAdapt instead proposes candidates meeting an incremental resource reduction, briefly fine-tunes them, and picks the highest-accuracy feasible candidate. Constructed iteration: a 100 ms model must reduce latency by at least ΔR = 10 ms. Candidate A reaches 88 ms and 89% accuracy; B reaches 90 ms and 90%; C reaches 94 ms and 91%. C fails the incremental budget; choose B among the feasible candidates, then repeat from B. The lecture describes short-term fine-tuning of 10k iterations, followed by long-term fine-tuning after the final budget is reached. That number is the slide's setup, not a universal requirement. [Lecture6, slide 48]

6 · Iterative pruning compounds the fraction that survives

The lecture defines one prune-and-fine-tune cycle as an iteration and raises target sparsity gradually. Its example progresses from 50% to 70% total sparsity and describes a 5× to 9× AlexNet parameter-compression improvement over a single aggressive step. These are course examples, not guarantees for another model. [Lecture6, slides 53–55]

Constructed case: start with 1,000 weights, remove 50%, leaving 500. To reach 70% total sparsity, retain 300 and remove 200 of the survivors: 200/500 = 40% of the remaining weights. Removing another 70% of survivors would leave 150 and yield 85% total sparsity. With fixed fraction q removed from survivors in each of t rounds, retention is (1 − q)t and total sparsity is 1 − (1 − q)t. Three rounds with q = 0.20 give 1 − 0.8³ = 48.8%, not 60%.

Fine-tuning updates surviving weights to compensate for lost contributions. Fixed masks must still be applied after updates so deleted weights do not unintentionally regrow. Rebuilt structured models preserve their smaller shapes directly. The slide recommends a fine-tuning learning rate typically 1/100 or 1/10 of the original: from 0.01, those examples are 0.0001 and 0.001. A held-out validation set checks accuracy; repeatedly selecting on the final test set can bias reported performance. [Lecture6, slide 52]

Retrieval practice: calculate before revealing

Why is 90% sparsity not necessarily a 10× smaller file?

1/(1−0.9)=10× counts nonzero values only. Dense zeros still occupy slots; sparse encodings add indices and headers. File compression needs an explicit storage format and measured file size.

A 200-weight layer is 50% sparse; an 800-weight layer is 25% sparse. What is global sparsity?

(200·0.5 + 800·0.25)/1,000 = 300/1,000 = 30%.

A dense 10×10 output has 16 filters, each seeing 8 channels through 3×3 kernels. Count MACs and FLOPs.

16·8·9·100 = 115,200 MACs; 230,400 FLOPs under the two-FLOP convention. There are 1,152 weights without bias.

At 50% current total sparsity, what fraction of survivors must be pruned to reach 80% total?

Remove (0.8−0.5)/(1−0.5) = 0.6 = 60% of survivors. Retention goes from 50% to 20% of the original.

Why can a 2× sparse kernel yield only 1.43× model speedup?

When it accelerates 60% of baseline time, new time is 60%/2 + 40% = 70%. The unaffected 40% limits overall speedup to 1/0.7.

Can the best isolated sensitivity choices guarantee final accuracy?

No. Layers interact; evaluate the combined pruned model and then fine-tune. Separately safe cuts can collectively damage accuracy.

What this does not show

These calculations teach budgeting rather than predict a device benchmark. The sparse-format examples omit headers, alignment, optimizer state, and activation buffers. Convolution counts omit bias and nonlinear operations. Latency bounds assume stated sustained rates and overlap. Accuracy recovery depends on data, model redundancy, criterion, and training schedule; none of the constructed accuracy tables is measured evidence.

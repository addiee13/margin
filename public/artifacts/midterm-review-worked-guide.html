1. Read the problem as a resource-accounting contract

Source pages 2–23

This guide explains the mathematical and conceptual question families in the supplied Mid-term Review.pdf. A yellow star in the actual PDF is a priority marker; the stars here identify those source topics, including repeated slides. The review has 98 pages and 42 genuinely starred pages. Five explicit example questions occupy pages 3–23. Their intent is to test whether you can connect the shape of a computation to its storage, activation memory, arithmetic, or pruning behavior.

The PDF says the exam covers Lectures 1–7 and uses multiple-choice, conceptual, and short-answer questions; it also describes separate undergraduate and graduate papers and a handwritten single-sided letter-size cheat sheet. These are source statements, not a prediction of the questions you will receive. [Review PDF pp. 2]

Every new exercise in this guide uses constructed inputs. These exercises preserve the review's operations and reasoning difficulty while changing dimensions, values, or the context. The solutions expose each step rather than giving a number without a method. Exact counts are exact integers; decimal floating-point boundary values are approximations where marked. No graph is treated as a hidden numerical table.

Use a three-column scratch table: given, formula, and answer with units. Parameter count means learned constants, activation count means runtime tensor elements, MAC count means multiply-accumulate operations, and measured latency means elapsed time on a specified system. A formula for one cannot silently replace another.

Notation throughout: B is batch size; Cᵢ and Cₒ are input/output channels or features; H,W are spatial sizes; K is kernel size; S is stride; P is symmetric padding; G is group count. Parameters and MACs ignore bias unless stated. Tensor layouts are written in the order shown by the course, without assuming every software library stores tensors in that order.

2. ★ Dense layers connect every output to every input

Source pages 3–5; 30; 32; 44; 56

A fully connected layer makes each output feature a weighted sum of all input features. If input X has shape (B,Cᵢ), then W has shape (Cₒ,Cᵢ), bias b has shape (Cₒ), and output Y has shape (B,Cₒ). With rows of X representing examples, the computation is Y=XWᵀ+b, where the bias is broadcast across rows. [Review PDF pp. 3–5, 32]

yj = Σi=1…Cᵢ wjixi + bj

Why does W have this shape? One output requires Cᵢ coefficients. There are Cₒ outputs, so there are Cₒ rows of Cᵢ coefficients. This gives CᵢCₒ weights and, when enabled, Cₒ biases. The weights are shared by all B examples; increasing the batch increases output elements and arithmetic, not the number of distinct learned constants.

Weights = CᵢCₒ; parameters with bias = CᵢCₒ+Cₒ; activations = BCₒ; MACs = BCᵢCₒ

The network diagram distinguishes depth, the number of successive layers, from width, the number of hidden features or neurons in a layer. Increasing width changes a layer’s feature dimensions and often increases parameters; increasing batch changes how many examples use those layers. These are separate axes of model shape. [Review PDF p. 30]

Source Example Question 1, fully explained

The input shape is (4,2), and there are 6 output neurons. Step 1: Cᵢ=2 and Cₒ=6. Step 2: W has shape (6,2), so the weights number 6×2=12. Step 3: each output has one bias, giving 6 more learned values. Therefore trainable parameters are 12+6=18. The output shape is (4,6). The last output-shape observation is an explanatory extension to the two questions asked on the slide. The source answer agrees. [Review PDF pp. 3–5]

A common wrong answer multiplies 18 by the batch size. That would imply four independent models. A batch applies the same model to four inputs, so 18 parameters remain 18 parameters.

Practice D1: Constructed: input (3,5), dense layer with 7 outputs and bias. Find weight shape, parameter count, output shape, and MACs.
  1. W=(7,5).
  2. Its 35 coefficients plus 7 biases give 42 parameters.
  3. Output is (3,7), so there are 21 output activations.
  4. For arithmetic, each of 3×7 outputs takes 5 MACs: 3×7×5=105 MACs.
  5. Bias additions are excluded from this MAC convention.
  6. Parameters and arithmetic have different batch dependence.
Practice D2: Constructed: input (2,9), dense layer with 4 outputs and bias. Which result changes if batch becomes 8?
  1. W=(4,9), weights=36, parameters=36+4=40, output=(2,4), and MACs=2×4×9=72.
  2. Changing B to 8 leaves W and the 40 parameters fixed but multiplies the activation count and MAC count by 4.
  3. The original output has 8 elements; the new output has 32.

Short-answer self-check: your explanation should name both feature dimensions, show the separate weight and bias terms, and explicitly state that batch does not change learned parameter count.

3. ★ Convolution counts local connections repeated across space

Source pages 33–35; 44–47; 56–57

A convolution filter sees a local receptive field rather than the whole input image. A standard 2D convolution has W shape (Cₒ,Cᵢ,Kₕ,K𝑤); each output channel has its own kernel, and the kernel is reused at every output position. Reuse is why parameter count is independent of image resolution even while arithmetic and activations grow with resolution. [Review PDF pp. 33–34, 45]

Hₒ = ⌊(Hᵢ+2Pₕ−Kₕ)/Sₕ⌋+1; Wₒ = ⌊(Wᵢ+2P𝑤−K𝑤)/S𝑤⌋+1

These shape formulas assume dilation 1, symmetric padding, and ordinary floor-based output sizing. If a problem changes dilation or uses a different padding convention, read that explicitly. The floor matters: with a stride greater than one, you cannot casually cancel terms and promise that doubling an input will double every output dimension exactly.

Weights = CₒCᵢKₕK𝑤; output activations = BCₒHₒWₒ; MACs = BCₒHₒWₒCᵢKₕK𝑤

Derivation: one output value is the dot product of CᵢKₕK𝑤 input/kernel pairs. There are BCₒHₒWₒ outputs. Multiply those two counts. The same weights participate repeatedly, so multiplying weight count by B or output area would confuse how often a weight is used with how many weights exist.

Practice C1: Constructed: B=1, input 4×16×16, 8 output channels, 3×3 kernel, stride 2, padding 1. Find shape, weights, and MACs.
  1. Hₒ=Wₒ=⌊(16+2−3)/2⌋+1=⌊15/2⌋+1=8.
  2. Output is 8×8×8.
  3. Weights=8×4×3×3=288.
  4. Output activations=8×8×8=512.
  5. Each activation needs 4×3×3=36 MACs, so MACs=512×36=18,432.
  6. With bias, parameters would be 288+8=296; the requested weights-only answer remains 288.
Practice C2: Constructed: B=1, input 3×15×15, 6 output channels, 5×5 kernel, stride 1, no padding. Find output and resource counts.
  1. Hₒ=Wₒ=15−5+1=11.
  2. Output is 6×11×11.
  3. Weights=6×3×25=450.
  4. Activations=6×121=726.
  5. MACs=726×75=54,450.
  6. No padding reduces spatial size; using 15×15 in the MAC formula would overcount outputs.

The starred 1D convolution uses the same reasoning on one spatial axis

For 1D convolution, input X has shape (B,Cᵢ,Wᵢ), output Y has shape (B,Cₒ,Wₒ), weights W have shape (Cₒ,Cᵢ,K), and bias has shape (Cₒ). Each output sees CᵢK inputs. With dilation 1, Wₒ=⌊(Wᵢ+2P−K)/S⌋+1; weights=CₒCᵢK; output activations=BCₒWₒ; MACs=BCₒWₒCᵢK. The 2D formulas add a second spatial kernel/output dimension rather than introducing a different counting principle. [Review PDF p. 33]

Grouped and depthwise convolutions require a different input-channel factor

With G groups, each output sees Cᵢ/G input channels. Assume G divides both channel counts. The formulas become weights=Cₒ(Cᵢ/G)KₕK𝑤 and MACs=BCₒHₒWₒ(Cᵢ/G)KₕK𝑤. Output activation count stays BCₒHₒWₒ. The review lists group and depthwise formulas alongside dense convolution. [Review PDF pp. 45, 57]

Depthwise convolution with one output per input channel has G=Cᵢ=Cₒ; weights=CᵢKₕK𝑤 and MACs=BCᵢHₒWₒKₕK𝑤. A subsequent pointwise 1×1 convolution has its own weights and MACs; it is not included just because the word “depthwise” appears.

Practice G1: Constructed: 8 input channels, 12 outputs, G=4, 3×3 kernel, output 10×10, B=1. Compare grouped and standard weights.
  1. Each output sees 8/4=2 input channels.
  2. Grouped weights=12×2×9=216; activations=12×100=1,200; MACs=1,200×18=21,600.
  3. Standard convolution would have 12×8×9=864 weights and 86,400 MACs, four times as many.
  4. A separate depthwise layer with 8 input/output channels and the same 10×10 output uses 8×9=72 weights and 7,200 MACs.
Practice G2: Constructed: 12 inputs, 16 outputs, G=4, 3×3 kernel, output 8×8, B=1. Also count a separate 12-channel depthwise layer.
  1. Grouped weights=16×(12/4)×9=432; activations=16×64=1,024; MACs=1,024×27=27,648.
  2. For the separate depthwise layer, weights=12×9=108; MACs=12×64×9=6,912.
  3. Do not compare layers as interchangeable architectures: their connectivity and output channels differ.

Pooling changes shape without learned weights

Max pooling selects the largest local input; average pooling computes a local average. The review shows channelwise pooling with kernel size equal to stride and no learnable parameters. A 2×2, stride-2 pool on an even-sized map halves H and W and preserves C. Its output still contains activations. In the review's MAC accounting table max pooling has zero MACs; that does not mean it takes zero comparisons or zero runtime. [Review PDF pp. 23, 35]

Nonlinear activations such as ReLU act after weighted sums. ReLU is max(0,x); ReLU6 additionally caps the value at 6. These functions are why stacking neural layers can express more than one linear transformation. For an ordinary ReLU on values [−2,0,3], the outputs are [0,0,3]; this is an explanatory microexample, not an additional architecture count. [Review PDF pp. 36]

4. ★ Activation memory depends on area and on what remains live

Source pages 6–8; 19–20; 51–53

The second source example asks why CNN memory is uneven across depth, and what doubling input resolution changes. Early layers usually retain large H×W maps, creating many activation elements. Later layers downsample their maps; more channels do not necessarily offset the reduced spatial area. Parameters can become a larger fraction of layer memory later. This is a tendency illustrated by the review's CNN plots, not a theorem that every CNN follows. [Review PDF pp. 6–8, 53]

Activation elements = BC×H×W; activation bytes = BC×H×W×(bits per activation)/8

If both H and W scale by a factor a while B and C are fixed, activation count scales by a². This explains the source's roughly fourfold increase when each image dimension doubles. Convolution kernel dimensions and channel counts do not change, so first-layer parameter count is unchanged. The “roughly” qualification matters when stride and rounding prevent exact doubling of output dimensions.

Practice M1: Constructed: a stride-1 same-size convolution produces 8×32×32. Input dimensions double; channels stay fixed. What changes?
  1. Original outputs=8×32×32=8,192.
  2. New outputs=8×64×64=32,768.
  3. Ratio=32,768/8,192=4.
  4. Weights do not change because Cᵢ,Cₒ and the kernel are fixed.
  5. MACs also increase fourfold because the kernel is applied at four times as many output positions.
Practice M2: Constructed: output 12×24×24 becomes 12×36×36, same convolution filter bank. Find count and ratio.
  1. Original activations=12×24²=6,912.
  2. New activations=12×36²=15,552.
  3. Ratio=(36/24)²=2.25.
  4. A 50% increase in each dimension means a 125% increase in area, not a 50% increase.
  5. The number of weights remains constant.

Total activation count is not peak activation memory

The review's AlexNet slide reports 932,264 total activation elements, including its 150,528 input elements. Output tensors alone sum to 781,736. Its simplified peak is input plus first-convolution output: 150,528+290,400=440,928. This convention counts the input as part of the total and uses adjacent live input/output buffers for the peak. It is an approximation to runtime memory, not a full allocator trace. [Review PDF pp. 20, 52]

To estimate a chain's peak under that convention, evaluate Aᵢ₋₁+Aᵢ for each operation, then take the maximum. Multiply by bytes per element. A runtime may reuse buffers, keep skip connections alive, allocate convolution workspaces, or keep training intermediates. Those effects can change the actual peak without changing the mathematical output tensor shapes.

Practice M3: Constructed: input 3×16×16 and output 8×16×16 coexist, FP32 activations. Estimate this operation's live activation bytes.
  1. Input count=3×256=768; output count=8×256=2,048.
  2. Live count=768+2,048=2,816.
  3. FP32 uses 4 bytes per element, so live bytes=2,816×4=11,264 bytes.
  4. This answer is for the specified two tensors and does not include weights or workspace.
Practice M4: Constructed: input 8×16×16 and output 16×8×8 coexist, FP16 activations. Estimate bytes.
  1. Counts are 8×256=2,048 and 16×64=1,024.
  2. Live count=3,072.
  3. FP16 uses 2 bytes each, giving 6,144 bytes.
  4. Although channels doubled, output activation count halved because spatial area fell by a factor of four.

Conceptual variant: why can a model with fewer parameters still run out of activation memory? Explainer: parameter count measures learned weight elements; activation count depends on batch, resolution, and feature maps. Keeping large early maps or several live branches can dominate memory even when the model's weight file is small. Name the relevant tensors instead of assuming that a smaller file guarantees a smaller working set.

6. ★ Arithmetic counts, storage, latency, and energy answer different questions

Source pages 21–22; 24–29; 38–61

The review's efficiency diagrams connect storage, computation, and memory to smaller, faster, greener deployment. Model compression bridges demand for AI computation and available hardware. It can improve one resource while leaving another as the bottleneck. Accuracy belongs in the comparison: an inexpensive model that fails the required task is not an adequate substitute. [Review PDF pp. 24–26, 39]

Latency is elapsed time for a specified task; throughput is the rate of completed work. A batched system can have high throughput while a single request waits for batch formation. Energy is work consumed over time. Reducing memory movement can matter greatly because a memory access and an arithmetic operation can have different energy costs; the table in the review illustrates this dependence without guaranteeing the same ratios on every device. [Review PDF pp. 40–42]

Throughput = completed items / elapsed seconds; energy = average power × seconds

MAC means multiply-accumulate, a←a+b×c. For matrix A of shape m×n times matrix B of shape n×k, the output has m×k entries and each entry has n multiply-accumulates, so MACs=mnk. In the review's convention one multiply and one add are two operations, making FLOPs≈2×MACs for floating-point math. FLOPs counts work; FLOPS means FLOPs per second. Integer computation can be reported as OPs/OPS rather than floating-point operations. [Review PDF pp. 21, 55, 60–61]

Practice A1: Constructed: multiply (2×5) by (5×4). Give output shape, MACs, and FLOPs under the review convention.
  1. Inner dimensions match.
  2. Output is 2×4, with 8 entries.
  3. Each entry uses 5 MACs, so total=40 MACs.
  4. At 2 FLOPs per MAC this is 80 FLOPs.
  5. Counting only output entries gives 8, which misses each dot product's work.
Practice A2: Constructed: multiply (3×2) by (2×6). How many MACs? Why is the count not the sum of matrix elements?
  1. Output is 3×6.
  2. Each of its 18 entries has a length-2 dot product, so MACs=3×2×6=36, corresponding to 72 FLOPs under the stated convention.
  3. Input storage counts elements once; arithmetic counts every use in each output dot product.
Practice T1: Constructed: 12 images complete in 48 ms at average power 20 W. Find throughput, mean time per completed image, and batch energy.
  1. Convert milliseconds: 48 ms=0.048 s.
  2. Throughput=12/0.048=250 images/s.
  3. Time per completed image=0.048/12=0.004 s=4 ms, an amortized batch figure, not an independently measured request latency.
  4. Batch energy=20×0.048=0.96 J, hence 0.08 J per image under equal allocation.
Practice T2: Constructed: 20 items complete in 0.10 s at 15 W. A system designer says “each request's latency is 5 ms.” Evaluate.
  1. Throughput=200 items/s.
  2. Amortized time per item is 0.10/20=0.005 s, but the statement about each request's latency does not follow.
  3. Each item in a jointly processed batch may wait about the entire 0.10 s plus queueing.
  4. Batch energy=15×0.10=1.5 J; energy per item=0.075 J.

Weight storage requires a bit width and a unit convention

Ignoring metadata and packing overhead, weight storage in bits is Nw, where N is parameter count and w is bits per parameter. Divide by 8 for bytes. Decimal MB is 10⁶ bytes; MiB is 2²⁰ bytes. The slide's approximate AlexNet example uses 61 million parameters: FP32 gives 244 million bytes (244 MB); INT8 gives 61 million bytes (61 MB). This is weight storage, not all inference memory. [Review PDF pp. 49]

Practice S1: Constructed: 2.4 million weights stored at 16 bits or ideally packed 4 bits. Find decimal MB and reduction factor.
  1. 16-bit storage=2,400,000×16/8=4,800,000 bytes=4.8 MB.
  2. Packed 4-bit storage=2,400,000×4/8=1,200,000 bytes=1.2 MB.
  3. The ideal weight-data reduction is 4×.
  4. Scales, zero points, alignment, and indices may add bytes; the prompt excludes them.
Practice S2: Constructed: 750,000 weights change from FP32 to INT8. Find bytes and explain whether latency must improve fourfold.
  1. FP32 storage=750,000×4=3,000,000 bytes; INT8 storage=750,000 bytes.
  2. Storage shrinks fourfold.
  3. Latency need not: kernels, conversion overhead, memory bandwidth, launch cost, and hardware support influence time.
  4. The computed factor is a weight-storage factor, not a timing measurement.

Conceptual variants about NAS and language-model capability

Variant: two image classifiers have equal measured accuracy, one uses fewer MACs; may we claim it is always faster? Explainer: the comparison supports a lower arithmetic count at the stated accuracy. Hardware measurements are still needed for latency. Neural architecture search can choose computationally cheaper architectures, but an operation mix that is easy to count may be difficult to execute efficiently. [Review PDF pp. 26]

Variant: distinguish zero-shot, few-shot, and chain-of-thought prompts. Explainer: zero-shot provides no worked demonstrations; few-shot supplies examples; chain-of-thought prompting supplies or elicits intermediate reasoning steps. They concern how the model is prompted, not a new formula for reducing parameter storage. The starred language-model slides illustrate reasoning gains and the cost of larger models. Their plotted results are source examples, not a universal guarantee that every larger model solves every problem. [Review PDF pp. 27–29]

Variant: a compression method saves memory but loses enough accuracy to miss the application requirement. Is it the best choice? Explainer: feasibility comes first: it must meet the requirement. Compare resources among feasible models, or discuss an explicit quality-resource tradeoff rather than announcing a win solely from file size. A strong exam answer names the criterion, states the tradeoff, and avoids claiming unmeasured hardware improvements.

7. ★ Pruning granularity determines what can actually become smaller

Source pages 62–68; 71

Pruning removes selected weights or activations while trying to retain useful task performance. The source frames this with a loss-minimization objective under a limit on the number of nonzero parameters. If Wₚ is the pruned weight tensor, ‖Wₚ‖₀ counts its nonzeros, N is the permitted count, and L is the task loss, the constraint is ‖Wₚ‖₀≤N. Despite the notation, the zero “norm” is a count, not a measure of coefficient magnitude. [Review PDF pp. 62]

Granularity means the size and structure of the unit removed. Elementwise pruning can remove arbitrary coefficients; channel pruning removes complete feature channels and their associated filters. Kernel and vector patterns sit between these extremes. Finer choice gives more freedom to select weights but can produce an irregular pattern that ordinary dense kernels still process. A smaller physical channel dimension can instead be represented as a smaller dense tensor and may accelerate more directly. [Review PDF pp. 64–68]

ChoiceWhat it gainsWhat it costs or needs
Unstructured coefficientsFlexible selectionSparse representation/kernels for speed; masks alone retain dense shape
Patterned blocksRegular sparse patternPattern constraints and supporting hardware
Whole channelsSmaller dense channel dimensionsLess freedom and downstream shape changes

Conceptual variant: a dense 100×100 matrix has 70% of coefficients masked to zero, but remains stored densely. Does it now have shape 30×100? Explainer: no. Arbitrary zero coefficients are not the same as removing 70 complete rows. Nonzero count changed; physical dimensions did not. To reduce a dense layer to fewer outputs, prune and rebuild complete output rows, biases, and connected downstream inputs.

Channel pruning changes the next layer too

For a conventional convolution A, removing output channels decreases its Cₒ. If convolution B consumes those outputs, the same deletion decreases B's Cᵢ. Counting only A misses a downstream saving and, worse, may describe incompatible tensor shapes. Rebuilding dimensions is part of applying structured pruning correctly.

Practice P1: Constructed: conv A has 8 input channels and 12 outputs; conv B has 12 inputs and 20 outputs. Both use 3×3 kernels. Remove 4 A output channels physically. Count weights before/after.
  1. A initially has 12×8×9=864 weights.
  2. It keeps 8 outputs, so A becomes 8×8×9=576.
  3. B must reduce its inputs from 12 to 8: 20×12×9=2,160 becomes 20×8×9=1,440.
  4. Total weights fall from 3,024 to 2,016, a saving of 1,008.
  5. The corresponding activation reduction depends on A's output spatial dimensions.
Practice P2: Constructed: A has 12 inputs, 16 outputs; B has 16 inputs, 24 outputs; both 3×3. Physically remove 4 A output channels. Explain both tensors.
  1. A weights: 16×12×9=1,728 becomes 12×12×9=1,296.
  2. B weights: 24×16×9=3,456 becomes 24×12×9=2,592.
  3. Combined weights fall from 5,184 to 3,888, saving 1,296, or 25%.
  4. B keeps its 24 outputs.
  5. It is B's input-channel dimension that shrinks.

State the source's N:M convention before calculating

Page 67 describes N:M sparsity as N elements pruned within each contiguous group of M. In that convention, survivors per group are M−N and sparsity=N/M. The common 2:4 case is ambiguous across conventions because it keeps and removes two either way. For a non-half case, declare the convention explicitly; do not silently replace the slide's wording with a different library convention. [Review PDF pp. 67]

  4. This is the review's classic half-sparse pattern.

8. ★ Magnitude, scale, and APoZ are different pruning signals

Source pages 9–11; 69–72

A criterion assigns importance to the units being considered. Magnitude pruning ranks elementwise coefficients by |w|, then removes those with the smallest magnitude. The source question W=[0.05,−0.9,1.2,0.02] gives absolute values [0.05,0.9,1.2,0.02], so 0.02 is pruned first. Ranking by signed value would incorrectly remove −0.9 first. [Review PDF pp. 9–11, 69]

The heuristic's intuition is that, for comparable activations, a small coefficient makes a small contribution. It is not proof of low loss sensitivity: an input with very large activation can multiply a small weight, and interactions or rescaling can change its relevance. The source's plain-language “least influence” answer describes a heuristic, not an exact causal measurement of loss impact.

Practice W1: Constructed: weights [−0.04,0.7,−0.2,0.01]. Prune the two smallest by magnitude.
  1. Absolute magnitudes are [0.04,0.7,0.2,0.01].
  2. Ascending order is 0.01, 0.04, 0.2, 0.7.
  3. Remove 0.01 and −0.04.
  4. The other two remain.
  5. Sign does not change the importance ranking.
Practice W2: Constructed: weights [−0.8,0.03,−0.01,0.6]. Which two are removed first, and why?
  1. Magnitudes are [0.8,0.03,0.01,0.6].
  2. The smallest two correspond to −0.01 and 0.03.
  3. This differs from sorting raw signed values: −0.8 is large in magnitude and should survive this heuristic.

Scaling-based pruning targets entire filters or channels

The source associates a trainable multiplicative scale with each convolution filter's output. A small scale suggests that output channel has little influence in the scaled representation, so its filter and output may be removed. When a signed scale is used, “small” here means small magnitude. The unit removed is a channel, unlike elementwise magnitude pruning. [Review PDF pp. 70]

Practice SCALE1: Constructed: channel scales [0.8,−0.05,0.3,1.1]. Remove one channel by absolute scale.
  1. Magnitudes [0.8,0.05,0.3,1.1] select channel 2, with scale −0.05.
  2. Remove the channel's associated filter and update downstream connectivity.
  3. The most negative number is not automatically most dispensable.
Practice SCALE2: Constructed: scales [−0.4,0.09,1.2,0.02]. Which channel is selected, and what should be checked after pruning?
  1. The smallest absolute scale is 0.02 on channel 4.
  2. Select that channel.
  3. Check accuracy after the removal, and rebuild downstream input dimensions if physically deleting it.
  4. A small scale is a selection signal rather than a guarantee that every input remains unaffected.

APoZ counts how often the neuron produces zero

ReLU creates zero outputs for nonpositive inputs. Average Percentage of Zeros (APoZ) estimates the fraction of a neuron's observed outputs that are zero across evaluation samples and spatial positions. The source states that smaller APoZ corresponds to greater importance. Thus a high-APoZ neuron is a candidate for removal because it is inactive more often in the observed sample. [Review PDF pp. 72]

APoZ = observed zero outputs / observed outputs; percentage APoZ = 100 × that fraction

Practice Z1: Constructed: neuron A has 6 zero outputs among 8 observations; B has 2 among 8. Which is pruned first by APoZ?
  1. A has 6/8=75%; B has 2/8=25%.
  2. A is zero more often and is the first candidate.
  3. Do not pick B merely because 25 is the smaller number: smaller APoZ means more frequently active and, under this heuristic, more important.
Practice Z2: Constructed: one channel has 9 zeros among 12 measured outputs; another has 3 among 12. Compare and name a limitation.
  1. APoZ values are 75% and 25%.
  2. The first channel is the removal candidate.
  3. The estimate depends on representative calibration/evaluation data; a channel mostly inactive on this sample might be important on rare inputs.
  4. Zero frequency alone does not measure the magnitude of its rare nonzero contributions.

Conceptual variant: one weight has low magnitude but its channel is active on almost all samples; another channel has high APoZ. Must the criteria agree? Explainer: no. One scores a coefficient and another scores a neuron's observed activity. They use different evidence and prune different units. State the requested criterion instead of combining unrelated scores without a rule.

9. ★ Layer sensitivity helps choose ratios, but interactions limit it

Source pages 12–15; 73–81

Different layers have different redundancy and sensitivity. The source's sensitivity-analysis procedure chooses one layer, tries pruning ratios, records accuracy for each, and repeats for other layers. A layer whose accuracy falls sharply at small pruning ratios is sensitive; another may tolerate heavier pruning. A shared ratio can therefore waste compressible capacity in one layer while damaging another. [Review PDF pp. 73–76]

The threshold illustration chooses layer-specific ratios while trying to preserve an overall quality level. When using a supplied table, identify the largest allowed rate whose accuracy is at least the threshold. Do not infer precise ratios from a blurry plot. Even accurate independent layer tests do not guarantee that their combined choices preserve accuracy: changing one layer changes signals arriving at later layers. This is the reason Source Example Question 4 says independent choices can overestimate robustness. [Review PDF pp. 12–15, 77–78]

Global sparsity = Σlayers ℓ Nℓrℓ / Σlayers ℓNℓ

Nℓ is that layer's original weight count and rℓ is the fraction pruned from that original count. A simple average of ratios is correct only when layer counts are equal. The weighting makes a large layer's pruning rate matter more to total nonzero count.

Practice R1: Constructed: layer A has 100 weights and may prune 20%; B has 300 and may prune 60%. Find global sparsity. Would 40% be right?
  1. A removes 100×0.20=20; B removes 300×0.60=180.
  2. Total removed=200 from 400, so sparsity=50%.
  3. The unweighted mean (20%+60%)/2=40% is wrong because B is three times larger.
  4. Meeting these independently allowed rates does not guarantee the combined model meets accuracy.
Practice R2: Constructed: A has 200 weights at 50% pruning; B has 800 at 25%. Find weighted overall sparsity.
  1. Removed counts are 200×0.5=100 and 800×0.25=200.
  2. Total=300 of 1,000, so overall sparsity=30%.
  3. A larger numerical rate in the smaller layer does not make it dominate the combined count.
Practice R3: Constructed sensitivity table: rates 0%,20%,40%,60% give accuracy [92,91,89,82] for A and [92,92,91,88] for B. Threshold 90%. Choose allowed rates.
  1. A can reach 20% because 91≥90, while 40% gives 89 and fails.
  2. B can reach 40% because 91≥90, while 60% gives 88 and fails.
  3. A is more sensitive at the tested rates.
  4. These are table-derived individual choices; evaluate the jointly pruned model before promising 90% overall.

AMC and NetAdapt should not be confused

Source Q4 asks which listed method formulates pruning as reinforcement learning: AMC, AutoML for Model Compression. The source diagram depicts an actor choosing compression actions and a critic/evaluation signal tied to the resulting model. In conceptual terms, state describes the current layer/model context, action chooses a pruning ratio, and a reward expresses the search objective. That is a different category from an APoZ importance score. [Review PDF pp. 12–15, 79–80]

NetAdapt is described as a rule-based iterative/progressive method that finds per-layer pruning ratios to meet a global resource constraint, with latency used as an example. Its resource goal is one reason to distinguish arithmetic counts from measured device performance. Iterative pruning with fine-tuning is a schedule; it is not itself the named reinforcement-learning ratio-search method. [Review PDF pp. 81–82]

Conceptual variant 1: “A policy chooses compression actions after observing layer information and gets a quality/resource reward.” Which review method fits? Explainer: AMC. Name the state/action/reward mechanism, not only the acronym.

Conceptual variant 2: “A procedure progressively adapts layer widths to meet a device-latency budget.” Which review method fits? Explainer: NetAdapt is the described resource-constrained iterative adaptation method. Do not select magnitude pruning merely because weights are eventually removed; magnitude is a criterion, not the global search mechanism.

Conceptual variant 3: independently pruning two layers barely changes accuracy, but pruning both causes a large drop. Is this a contradiction? Explainer: no. The first deletion alters the intermediate representation, changing what redundancy remains for the next deletion. Tests performed on the original model do not measure the same distributions as joint pruning.

10. ★ Repeated pruning rates compound on the survivors

Source pages 63; 82

The review recommends iterative pruning with fine-tuning rather than increasing directly to a very high target in one destructive step. The model may adapt after each stage. It describes gradually increasing target sparsity; any numeric schedule must state whether its rates refer to the original model or to current survivors. [Review PDF pp. 63, 82]

Survivors after k equal survivor-based rounds = N₀(1−r)k; cumulative sparsity = 1−(1−r)k

Here N₀ is original parameter count and r is the fraction of remaining weights removed each round. The derivation is repeated multiplication: after one round N₀(1−r), after two N₀(1−r)². Rates do not add because each round operates on a smaller population. If the prompt gives absolute target sparsities instead, calculate retained counts relative to N₀ at each target.

Practice I1: Constructed: start with 1,000 weights; remove 20% of remaining weights in each of three rounds. Find survivors and original-count sparsity.
  1. Round 1 retains 1,000×0.8=800.
  2. Round 2 retains 800×0.8=640.
  3. Round 3 retains 640×0.8=512.
  4. Removed count=488, so cumulative sparsity=48.8%.
  5. Adding the three 20% rates to claim 60% would use the wrong denominator.
Practice I2: Constructed: start with 800 weights; remove 25% of remaining weights twice. Give survivor counts and total sparsity.
  1. First round: 800×0.75=600.
  2. Second: 600×0.75=450.
  3. Total removed=350; cumulative sparsity=350/800=43.75%.
  4. This schedule is distinct from specifying 25% then 50% original-count target sparsity.

Conceptual variant: why fine-tune between pruning stages? Explainer: removal changes the available pathways and the distribution of intermediate features. Updating the surviving weights lets the model adapt before the next loss of capacity. Fine-tuning may improve recovery, but neither the slide nor this argument promises that an arbitrarily sparse model keeps its original accuracy.

11. ★ Integer and fixed-point decoding begin with the representation

Source pages 83–85

A bit pattern has no unique numerical meaning until its representation is stated. For unsigned n-bit integers, every position has a positive power-of-two weight. For sign-magnitude, the leading bit supplies the sign and the remaining bits give magnitude. For two's complement, the leading bit has weight −2ⁿ⁻¹ and the remaining positions keep positive weights. The latter can also be decoded by taking the unsigned value U and subtracting 2ⁿ if the sign bit is 1. [Review PDF pp. 83–84]

Unsigned: U=Σ bi2i; two’s complement: value = U if bn−1=0, else U−2n

The source's 8-bit pattern 11000000 is unsigned 128+64=192. As sign-magnitude it is negative magnitude 1000000₂=64, so −64. As two's complement it is 192−256=−64. Those two signed answers happen to coincide for this example; the conventions are not equivalent. “Signed” on page 84 should be read as the sign-magnitude category introduced on page 83.

Practice INT1: Constructed: decode 10100101 as unsigned, sign-magnitude, and two's complement.
  1. Unsigned: 128+32+4+1=165.
  2. Sign-magnitude: the leading 1 makes the remaining magnitude 0100101₂=32+4+1=37 negative, giving −37.
  3. Two's complement: 165−256=−91.
  4. This variant exposes the distinction hidden in the source's −64 coincidence.
Practice INT2: Constructed: decode 11110000 in all three conventions.
  1. Unsigned: 128+64+32+16=240.
  2. Sign-magnitude: −(64+32+16)=−112.
  3. Two's complement: 240−256=−16.
  4. The highest bit changes sign convention, not simply “make the unsigned number negative.”

For n bits, unsigned range is 0 to 2ⁿ−1; sign-magnitude range is −(2ⁿ⁻¹−1) to +(2ⁿ⁻¹−1) with two zero patterns; two's complement range is −2ⁿ⁻¹ to 2ⁿ⁻¹−1 with one zero pattern. The asymmetric two's-complement range includes one more negative value. [Review PDF pp. 83]

Fixed-point applies a scale after signed decoding

With F fractional bits, decode the bits as a two's-complement integer I, then compute x=I×2⁻ᶠ. This gives spacing 2⁻ᶠ. More fractional bits improve resolution but reduce range for the same total width. The source's 00110001 with four fractional bits has integer I=49, so x=49/16=3.0625. [Review PDF pp. 85]

Practice FX1: Constructed: 8-bit two's-complement fixed-point 11101000 with F=4. Decode.
  1. Unsigned U=232; the sign bit is 1, so signed I=232−256=−24.
  2. Scale by 2⁻⁴=1/16: x=−24/16=−1.5.
  3. Decode the signed integer first; using a positive sign and shifting the decimal point afterward gives the wrong sign.
Practice FX2: Constructed: 00110110 with F=3. Decode and compare with the F=4 format's range.
  1. The integer is 54, so x=54/8=6.75.
  2. An 8-bit F=4 format has range −128/16=−8 to 127/16=7.9375, with step 0.0625.
  3. The F=3 format has coarser steps but a larger range; the meaning of the same stored integer depends on F.

12. ★ Floating-point decoding separates sign, exponent, and fraction

Source pages 86–95

For a normal binary floating-point number, a sign bit s chooses sign, an exponent field E selects a power of two, and an m-bit fraction field F supplies the fractional part f=F/2ᵐ. With e exponent bits, bias β=2ᵉ⁻¹−1. The normal finite formula is x=(−1)ˢ(1+f)2ᴱ⁻ᵝ. The leading 1 is implicit and is not stored in the fraction bits. It exists only for normal numbers. [Review PDF pp. 86–87, 93]

Normal finite: x=(−1)s(1+F/2m)2E−β, for 1≤E≤2e−2

FP32 has e=8, m=23, β=127. FP16 has e=5, m=10, β=15. The source's 0.265625 normalizes as 1.0625×2⁻²; this yields sign 0, E=125, and fraction 0.0625=2⁻⁴, so only the fourth fraction bit is 1. The stored exponent is 125, while the actual exponent is −2. [Review PDF pp. 86]

The FP16 source example has sign 1, E=10001₂=17, and fraction bits 1100000000. Their fractional value is 1/2+1/4=0.75. Thus x=−(1+0.75)×2¹⁷⁻¹⁵=−1.75×4=−7. Reading the fraction bits as integer 768 without dividing by 1,024 would produce a wildly wrong significand. [Review PDF pp. 95]

Practice F1: Constructed FP16: s=0, E=10000₂, fraction=0100000000. Decode.
  1. E=16, so actual exponent=16−15=1.
  2. Fraction f=1/4=0.25.
  3. Normal significand=1.25, sign positive.
  4. Value=1.25×2=2.5.
  5. Equivalently F=256 and f=256/1,024.
Practice F2: Constructed FP16: s=1, E=01110₂, fraction=1000000000. Decode.
  1. E=14, so exponent=14−15=−1.
  2. Fraction=0.5; normal significand=1.5.
  3. Value=−1.5×2⁻¹=−0.75.
  4. The leading exponent bit 0 is part of E; it is not another sign.
Practice F3: Constructed FP32: s=0, E=129, first fraction bits 010 and all remaining bits zero. Decode.
  1. Actual exponent=129−127=2.
  2. Fraction=2⁻²=0.25, so value=1.25×4=5.
  3. The fraction width does not change the positional value of its first three bits.
Practice F4: Constructed FP32: s=1, E=126, first fraction bit 1 and all remaining bits zero. Decode.
  1. Actual exponent=−1; fraction=0.5.
  2. Thus value=−1.5×2⁻¹=−0.75.
  3. This equals practice F2's value even though the two formats have different field widths and biases.

Subnormal numbers fill the gap near zero using x=(−1)ˢ(F/2ᵐ)2¹⁻ᵝ. The exponent is fixed at 1−β and the implicit leading 1 is removed. Without this exception, setting every field to zero would still give a nonzero number under the normal formula. The source develops zero, subnormal, infinity, and NaN cases on separate slides. [Review PDF pp. 88–93]

  1. E=0 and F>0 identifies a subnormal.

13. ★ Boundary formulas explain range, precision, and tiny formats

Source pages 89–97

The smallest positive subnormal uses fraction integer 1. The largest positive subnormal fills every fraction bit, giving f=1−2⁻ᵐ. The smallest normal uses E=1,F=0; the largest finite normal uses the largest nonreserved exponent E=2ᵉ−2 and all fraction bits 1. Deriving these four cases is more reliable than memorizing approximate decimal constants. [Review PDF pp. 90–94]

Smallest subnormal = 21−β−m; largest subnormal = (1−2−m)21−β

Smallest normal = 21−β; largest finite = (2−2−m)2(2ᵉ−2)−β

Practice B1: Constructed exam variant: derive the four positive FP16 boundaries using e=5,m=10,β=15.
  1. Minimum subnormal=2¹⁻¹⁵⁻¹⁰=2⁻²⁴≈5.960464478×10⁻⁸.
  2. Maximum subnormal=(1−2⁻¹⁰)2⁻¹⁴=≈6.097555161×10⁻⁵.
  3. Minimum normal=2⁻¹⁴=≈6.103515625×10⁻⁵.
  4. Maximum finite=(2−2⁻¹⁰)2¹⁵=65,504.
  5. The max-subnormal/min-normal gap is exactly one subnormal step, 2⁻²⁴.
Practice B2: Constructed exam variant: derive the FP32 largest subnormal and minimum normal using m=23,β=127.
  1. Largest subnormal=(1−2⁻²³)2⁻¹²⁶≈1.175494211×10⁻³⁸; minimum normal=2⁻¹²⁶≈1.175494351×10⁻³⁸.
  2. Their difference is 2⁻¹⁴⁹, the smallest positive subnormal.
  3. Filling fraction bits approaches the smallest normal from below but does not equal it.

For normal numbers in the interval [2ᵏ,2ᵏ⁺¹), one fraction-bit unit changes x by 2ᵏ⁻ᵐ. Exponent width primarily controls representable range; fraction width primarily controls local precision. More bits in one field do not automatically improve the other. FP32 and BF16 both have eight exponent bits, while FP32's larger fraction field resolves much smaller relative differences. The review compares FP32, FP16, BF16, and FP8 layouts. [Review PDF pp. 94, 96]

14. Quantization maps a continuous choice onto a discrete set

Source pages 98; extension

The last review page defines quantization as restricting values from a continuous or large set to a discrete set. Its examples connect continuous signals to quantized levels and images to reduced colors. A quantized value introduces quantization error: the difference between the original and reconstructed values. The slide does not supply an affine scale/zero-point formula or a full quantization algorithm. The simple numerical rule below is therefore a clearly labeled explanatory extension, useful for practicing the definition without attributing an unsupplied formula to the Lecture 7 slides. [Review PDF pp. 98]

Extension: q = clip(round(x/s),qmin,qmax); reconstructed x̂=sq; error=|x−x̂|

Assume positive scale s, integer output q, zero point 0, nearest rounding, and the specified integer bounds. No example below is an exact halfway tie, so tie-breaking does not affect these answers. Without clipping, nearest rounding error is at most s/2. Clipping can create a larger error for inputs outside representable range.

Practice Q1: Constructed extension: s=0.25, signed integer bounds [−8,7], x=0.62. Quantize and reconstruct.
  1. x/s=0.62/0.25=2.48.
  2. Nearest integer=q=2; it is inside bounds.
  3. Reconstruct x̂=2×0.25=0.5.
  4. Absolute error=|0.62−0.5|=0.12, below s/2=0.125.
Practice Q2: Constructed extension: s=0.2, bounds [−8,7], x=−0.88. Quantize and reconstruct.
  1. x/s=−4.4, so nearest integer=q=−4.
  2. Reconstructed value=−0.8; error=0.08.
  3. Negative inputs round by closeness on the number line; taking absolute value first would discard the sign.
Practice Q3: Constructed extension: s=0.25, bounds [−8,7], x=2.0. Why does the half-step error bound fail?
  1. x/s=8; rounding gives 8 but the allowed maximum is 7.
  2. Clip to q=7 and reconstruct 1.75.
  3. Error=0.25, larger than 0.125.
  4. The half-step bound assumed the input lies in the covered range without clipping.

A short-answer grading lens

A mathematical answer is complete when it states the representation or counting convention, substitutes the supplied numbers, shows the result with units, and explains a boundary condition. A conceptual answer is complete when it names the mechanism, follows its cause to its effect, and states what evidence would be needed for any practical claim. An answer that gives the correct acronym without explaining why it fits is weaker preparation than an answer that connects the method to the prompt.

Lecture 7: Number Formats and Quantization

A finite bit pattern is a promise about which numbers a machine can represent. Learn to read that promise, calculate its error, and explain why more range and more precision compete for the same bits.

1 · Bits do not identify a number until the representation is known

Start with 11000000, the review’s integer exercise. Reading it as unsigned gives 192. Reading the first bit as a sign and the remaining seven as a magnitude gives −64. Reading it as two’s complement also gives −64. The last two happen to agree for this pattern, so this example alone cannot teach you how to distinguish those representations. The preceding source page explicitly names sign-magnitude under its “signed integer” heading. [Review, pages 83–84]

Let n be the bit width and bi the bit at position i, counting from the right starting at 0. Each bit is 0 or 1. Unsigned decoding is simply a weighted sum of powers of two:

u = Σi=0n−1bi2i

For eight bits, positions weigh 128, 64, 32, 16, 8, 4, 2, 1. Thus 11000000 means 128 + 64 = 192. The unsigned range is 0 through 2n − 1 because all-one bits add to the geometric sum 1 + 2 + … + 2n−1.

In sign-magnitude, the first bit s contributes a sign, not an additional magnitude digit. Decode the remaining n−1 bits as a nonnegative integer m, then compute (−1)sm. Its range is −(2n−1 − 1) through +(2n−1 − 1); two codes represent zero. For 11000000, s = 1 and the magnitude 1000000 is 64, hence −64.

In two’s complement, the leftmost bit has negative place value. All other positions retain their usual positive place values:

v = −bn−12n−1 + Σi=0n−2bi2i

The eight-bit pattern therefore gives −128 + 64 = −64. There is one zero, and the range is −128 through 127. Another decoding route is useful: first compute unsigned u; if the top bit is 1, subtract 2n. Here 192 − 256 = −64. This is the same formula because changing the top position from +128 to −128 subtracts 256.

Worked variant: one pattern, three different answers

Interpret 10110110 in all three schemes. Unsigned: 128 + 32 + 16 + 4 + 2 = 182. Sign-magnitude: minus (32 + 16 + 4 + 2) = −54. Two’s complement: −128 + 32 + 16 + 4 + 2 = −74. The difference is a decoding rule, not a change in the stored bits.

Practice 1 · Similar formula, different pattern

Decode 11100101 as unsigned, sign-magnitude, and two’s complement. Show the place values before giving the three results.

Worked explanation

Unsigned is 128 + 64 + 32 + 4 + 1 = 229. Sign-magnitude excludes the sign bit from the magnitude: −(64 + 32 + 4 + 1) = −101. Two’s complement is 229 − 256 = −27. A negative sign by itself does not tell you which signed representation is intended.

On an exam, write the representation next to the answer; “signed” alone is too vague unless the question defines its convention. For this review, its explicitly labeled sign-magnitude branch supplies the intended meaning. Do not assume that every signed format is sign-magnitude or that the review’s accidental equal answers establish equivalence.

2 · Fixed point moves the binary point without changing the stored integer

The review encodes 00110001 in an eight-bit, two’s-complement format with four fractional bits. The bit pattern has integer value 49. Scaling by 2−4 makes its represented real value 49/16 = 3.0625. The slide shows the direct fractional-place-value route and this integer-then-scale route side by side. [Review, page 85]

Let v be the signed stored integer and f the number of fractional bits. Define the real represented value x̂, read “x hat,” by

x̂ = v × 2−f

The binary point is a convention shared by all values in this format; no separate exponent is stored with each value. Adjacent integers differ by 1, so adjacent represented reals differ by Δ = 2−f. For f = 4, the step is 1/16 = 0.0625. The eight-bit range becomes −128/16 through 127/16, or −8 through 7.9375.

Trace the review’s value in both directions

Place the binary point as 0011.0001. The leading bit has weight −2³; the other integer positions have weights 2², 2¹, 2⁰. The fractional positions have weights 2−1, 2−2, 2−3, 2−4. The nonzero entries contribute 2 + 1 + 1/16 = 3.0625. Alternatively, 00110001 is 32 + 16 + 1 = 49; 49 × 2−4 gives the same result.

Worked variant: decode a negative fixed-point value

With the same eight-bit/four-fractional-bit convention, 11010110 has unsigned value 214. Two’s-complement integer value is 214 − 256 = −42. Divide by 16: x̂ = −2.625. Direct place values also work: −8 + 4 + 1 + 0.25 + 0.125 = −2.625. Applying the sign only to the fractional tail would be wrong; the negative top-bit weight applies to the entire integer decoding.

Encoding reverses the operation. Given desired x, choose an integer close to x2f. This workbook uses rounding to nearest with ties to even and clipping to the allowed integer range when necessary; the source fixed-point slide defines the representation but does not specify a rounding policy. These rounding/clipping exercises are constructed extensions.

Practice 2 · Encode exactly, then quantify an approximation

In the same format, encode 1.6875. Next encode 1.7 using the stated rounding policy. Give the stored integer, bits, represented value, and signed error x̂ − x.

Worked explanation

For 1.6875, multiply by 16: 27 exactly. Integer 27 is 00011011; decoding gives 27/16 = 1.6875 with zero error. For 1.7, multiply by 16: 27.2. Nearest integer is 27, giving the same bits and represented value. Error is 1.6875 − 1.7 = −0.0125. Its absolute size 0.0125 is below the unsaturated nearest-rounding limit Δ/2 = 0.03125.

Keeping eight total bits but increasing f from 4 to 6 shrinks the step from 1/16 to 1/64. The range also shrinks to −2 through 127/64 = 1.984375. This is a concrete range/precision tradeoff: the former exactly represented value 3.0625 no longer fits. A smaller step is useful only if the values you need are still inside the range.

3 · A normal floating-point value combines a significand and a scale

Floating point stores a sign, an exponent field, and a fraction field. A binary32 value uses 1 sign bit, 8 exponent bits, and 23 fraction bits. The review normalizes its example 0.265625 as 1.0625 × 2−2; the exponent determines the scale and the significand determines the position within that scale. [Review, pages 86–87]

Use consistent notation: s is the sign bit; e the exponent-field width; m the fraction-field width; E the exponent field interpreted as an unsigned integer; F the fraction field interpreted as an unsigned integer. The mathematical fraction is F/2m. The exponent bias is β = 2e−1 − 1. For binary32, β = 127; for binary16, β = 15.

x = (−1)s(1 + F/2m)2E−β
Normal finite values: 1 ≤ E ≤ 2e − 2

The initial 1 of a normalized binary significand is not stored. For example, binary 1.101 has significand value 1 + 1/2 + 1/8 = 1.625. The stored fraction begins 101 and contributes 0.625. This hidden leading bit is why a normal binary32 number has 24 significant binary digits despite having only 23 fraction-field bits.

The bias does not change the represented exponent; it changes how that exponent is stored. If the real power is −2, the binary32 exponent field stores E = −2 + 127 = 125. To decode, subtract the bias and recover −2. The source motivates bias as a way to store negative and positive exponents in a nonnegative bit field. [Review, page 87]

These formulas are for normal finite numbers. A zero exponent field switches to the zero/subnormal rule, and an all-one exponent field switches to infinity/NaN. Those cases are part of the decoding contract, not optional corrections. The source headings that say “Exponent ≠ 0” must be read together with its later special-pattern table; they do not imply all-one exponents are normal. [Review, pages 92–93]

4 · Encoding a decimal value means normalizing its binary expansion

The starred source example: encode 0.265625 in binary32

  1. Make the fraction exact. 0.265625 = 17/64 = 1/4 + 1/64, so binary is 0.010001.
  2. Normalize. Move the point two places right: 1.0001 × 2⁻². The significand is 1 + 1/16 = 1.0625.
  3. Encode sign. The number is positive, so s = 0.
  4. Encode exponent. Real exponent is −2; stored exponent is 125. Its eight-bit binary pattern is 01111101.
  5. Encode fraction. Drop the hidden leading 1. Store 0001 and pad with zeroes to 23 bits: 00010000000000000000000.
  6. Check by decoding. (1 + 1/16)2125−127 = (17/16)/4 = 17/64 = 0.265625.
0 | 01111101 | 00010000000000000000000

The review gives this exact normalized value and field interpretation; the step-by-step binary decomposition above makes its arithmetic explicit. There is no rounding error because 17/64 has a finite binary expansion that fits well within the field width. [Review, page 86]

Practice 3 · Encode −6.5 with the same difficulty

Give binary32 sign, exponent field, fraction field, and a reverse calculation proving your answer.

Worked explanation

Magnitude 6.5 = binary 110.1 = 1.101 × 2². Sign is 1. Stored exponent is 2 + 127 = 129 = 10000001. The fraction 101 means 1/2 + 1/8 = 0.625; pad to 23 bits. Fields are 1 | 10000001 | 10100000000000000000000. Reverse calculation is −(1 + 0.625)2² = −6.5. Do not store 6 as the exponent: the exponent is a power, not the integer part of the original value.

For a number whose binary expansion does not terminate within the available fraction bits, you need a rounding rule. You cannot merely discard bits and claim the stored value is exact. This workbook separates exact source-style encoding questions from explicitly rounded extensions so that the question supplies enough information to give one answer.

5 · FP16 changes the field widths, not the method

Binary16 uses 1 sign bit, 5 exponent bits, and 10 fraction bits. Its bias is 15. The review asks you to decode 1 | 10001 | 1100000000. The first task is to keep the field boundaries intact; treating the full 16-bit pattern as an ordinary signed integer answers a different question. [Review, pages 94–95]

The source’s −7 calculation

Sign 1 gives a negative value. Exponent 10001 is 17, so real exponent is 17 − 15 = 2. Fraction 1100000000 is 1/2 + 1/4 = 0.75, not integer 110 and not 768 as a real fraction. The significand is 1.75. Therefore x = −1.75 × 2² = −7. Alternatively, fraction integer F = 768; F/1024 = 0.75 gives the same result.

Practice 4 · A new FP16 normal value

Decode 0 | 10000 | 0110000000. Explain what each field contributes.

Worked explanation

Sign is positive. E = 16, so the scale is 216−15 = 2. The fraction is 0/2 + 1/4 + 1/8 = 3/8 = 0.375. Thus x = (1 + 0.375)2 = 2.75. A wrong answer 0.75 forgets the hidden leading 1.

Practice 5 · Encode a small negative FP16 value

Encode −0.15625 exactly. Give the exponent and fraction fields, then decode to check.

Worked explanation

Magnitude 0.15625 = 5/32 = binary 0.00101 = 1.01 × 2⁻³. Sign is 1. Stored exponent is −3 + 15 = 12 = 01100. Fraction is 1/4 = 0.25, so store 0100000000. Fields: 1 | 01100 | 0100000000. Decoding gives −(1 + 0.25)2−3 = −1.25/8 = −0.15625.

Writing the field widths explicitly prevents a common transfer mistake: subtracting the binary32 bias 127 from an FP16 exponent. A format name controls the bias and bit boundaries together. A 16-bit storage width alone is insufficient because BF16 has different exponent/fraction widths.

6 · Subnormals fill the gap between zero and the smallest normal value

If the normal formula always included a leading 1, setting the fraction to zero would still leave a nonzero significand. The review therefore changes the rule when E = 0: remove the hidden 1 and use a fixed exponent 1 − β. This yields zero when the fraction is zero and a sequence of small nonzero values when it is not. [Review, pages 88–89]

x = (−1)s(F/2m)21−β,   E = 0

The exponent is 1 − β, not 0 − β. This choice makes the gap from the largest subnormal to the smallest normal exactly one subnormal step. To see why, let the smallest positive subnormal have fraction integer F = 1. Its value is

δ = 21−β−m

Subnormals are integer multiples Fδ for 1 ≤ F ≤ 2m − 1. The smallest positive normal has E = 1 and F = 0, giving 21−β = 2mδ. The largest subnormal is therefore one δ below it:

largest positive subnormal = (1 − 2−m)21−β
= smallest positive normal − δ

The review’s binary32 boundary

For β = 127 and m = 23, smallest subnormal is 2−149. Smallest normal is 2−126. Largest subnormal has all 23 fraction bits set to 1, giving (1 − 2−23)2−126 = 2−126 − 2−149. This is the review’s displayed result. Keep the powers exact: writing a rounded decimal for both boundary values can hide the tiny difference. [Review, pages 90–91]

Practice 6 · Transfer the same boundary derivation to FP16

Find the smallest positive subnormal, smallest positive normal, and largest positive subnormal for binary16. Give exact powers and the boundary gap.

Worked explanation

With β = 15 and m = 10, δ = 21−15−10 = 2−24. Smallest normal is 2−14. Largest subnormal is (1 − 2−10)2−14 = 2−14 − 2−24. The gap is exactly 2−24. This derivation changes field widths while preserving the source’s reasoning.

Practice 7 · Decode a subnormal instead of a normal

Decode FP16 0 | 00000 | 0000000011. Why is using 1 + fraction wrong?

Worked explanation

E = 0 triggers the subnormal branch. Fraction integer is F = 3; value is (3/1024)2−14 = 3 × 2−24. Adding a hidden 1 would jump to a different scale and destroy the intended small-value encoding. The question is the same decoding task as Practice 4, but the exponent branch changes the formula.

Subnormal steps have constant absolute spacing δ. As values approach zero, that same absolute step becomes a larger fraction of the value. Consequently the relative precision available near zero declines. This is a mathematical consequence of Fδ; it does not by itself tell you whether any particular accelerator executes subnormal arithmetic normally or flushes it to zero.

7 · Classify the exponent before doing arithmetic

The source reserves the all-one exponent field for infinities and NaNs. A zero fraction then means infinity; a nonzero fraction means NaN, “not a number.” The sign distinguishes +∞ and −∞; a NaN bit pattern does not encode an ordinary real number with a usable magnitude. [Review, pages 92–93]

Practice 8 · A short conceptual classification question

For FP16, classify the fields below without forcing every pattern through the normal formula: A 0|00000|0000000000; B 1|00000|0000000000; C 0|11111|0000000000; D 1|11111|0000000001.

Worked explanation

A is +0; B is −0; C is +∞; D is NaN. D is not “negative infinity” because its fraction is nonzero. The visible sign bit does not turn a NaN into a finite negative number. The right first move is classification by E and F.

All-zero and all-one exponent fields are branch conditions; check them before subtracting a bias and inserting a leading 1. Also distinguish the exponent field from the numerical exponent: a real exponent of zero corresponds to a normal value whose stored exponent equals the bias.

8 · Fraction bits determine local spacing; exponent bits determine reachable scales

The review compares FP32 (8 exponent/23 fraction), FP16 (5/10), and BF16 (8/7), emphasizing range versus precision. FP16 and BF16 both use 16 bits, but BF16 spends more of them on exponent range while FP16 spends more on fraction precision. This comparison concerns their represented values, not an automatic ranking of model accuracy or runtime. [Review, page 94]

Within a normal binary interval [2k, 2k+1), increasing the fraction integer F by one increases the significand by 2−m. Multiplying by 2k gives the spacing

ULP in [2k, 2k+1) = 2k−m

ULP means “unit in the last place,” the local spacing between adjacent representable normal values. This derivation is an extension of the source field-width comparison. It explains why floating-point spacing grows with magnitude: multiplying by a larger scale enlarges the same fraction-field step.

Worked spacing comparison at 1

At the start of [1, 2), k = 0. Binary32 spacing is 2−23; binary16 spacing is 2−10 = 1/1024; BF16 spacing is 2−7 = 1/128. BF16 spacing here is eight times FP16 spacing. Around magnitude 8, binary16 has k = 3 and spacing 23−10 = 1/128 = 0.0078125. FP16 has not lost fraction bits; its exponent scale made the absolute step larger.

Practice 9 · Rounding is a format-plus-policy question

Consider FP16 at 1. The next value is 1 + 2−10. Under nearest, ties-to-even rounding, where does x = 1 + 2−11 go? Explain why an answer requires the rounding rule.

Worked explanation

x is exactly halfway between 1 and 1 + 2−10. At the lower value, the fraction integer F = 0 is even; at the upper value F = 1 is odd. Ties-to-even chooses 1. A different tie rule could choose differently. The signed error is −2−11, exactly minus half the spacing. This policy is stated for the exercise; it is not specified by the review’s field-width picture.

More exponent bits can prevent overflow for a wider magnitude range, but do not guarantee better resolution around a given number. More fraction bits reduce local rounding error, but do not prevent overflow if the exponent range is too small. Useful answers name the value distribution and the failure being prevented instead of simply saying one format is “more accurate.”

FP8 also needs a specific convention, not just an eight-bit width

Page96 gives two NVIDIA FP8 examples: E4M3 has one sign bit, four exponent bits, and three fraction bits; E5M2 has one sign bit, five exponent bits, and two fraction bits. The source explicitly says its E4M3 example has no infinity encoding, uses sign|1111|111 for NaN, and has largest finite positive pattern 0|1111|110 with value 448. Its E5M2 example reserves sign|11111|00 for infinity and nonzero fraction at that exponent for NaN, with maximum finite positive pattern 0|11110|11 equal to 57344. [Review, page 96]

Explain the two maximum-value calculations

For the illustrated E4M3 convention, bias 7 and fraction110 give significand 1 +1/2+1/4=1.75; stored exponent 15 gives real exponent 8. Thus 1.75×2⁸=448. The largest exponent field still contains finite encodings in this convention; only the specified fraction 111 at that field is NaN. For the illustrated E5M2 convention, bias 15 and fraction11 give 1.75; exponent 30 gives real exponent 15. Thus 1.75×2¹⁵=57344. Exponent31 is unavailable for normal finite values because it is the infinity/NaN branch. The bias values here are the conventions consistent with the slide’s named patterns and results; the maximum-value arithmetic is an explanatory derivation.

Practice · Compare two FP8 designs without copying FP32 rules

A question describes precisely the two source conventions. Which has the larger maximum finite magnitude? Which devotes more bits to resolving the significand? Why would classifying every all-one exponent as infinity/NaN fail for one of them?

Model explanation

E5M2 reaches 57344, larger than E4M3’s 448. E4M3 uses three fraction bits instead of two, so at a shared normal scale it has finer fraction resolution. The source’s E4M3 convention retains finite encodings at exponent 1111; the specified fraction 111 gives NaN and there is no infinity. An unqualified IEEE-binary32 special-case rule would misclassify valid E4M3 numbers. The format’s documented contract controls decoding.

9 · Low-bit formats use different codebooks, even with the same four-bit budget

The starred low-bit comparison shows INT4 beside FP4 E1M2, E2M1, and E3M0. “E1M2” means one exponent bit and two fraction bits in addition to one sign bit; the other names describe the same allocation rule. These source examples are their own finite low-bit conventions. Do not transplant binary32’s infinity reservation without checking the format. The source lists finite maximum values 3.5, 6, and 16 for these FP4 illustrations. [Review, pages 96–97]

Trace three source FP4 patterns

E1M2 0|0|01: source subnormal formula is 0.25 × 2¹ = 0.5. Its maximum positive 0|1|11 is (1 + 0.75)2¹ = 3.5.

Practice 10 · Reason from the source codebook

Which source FP4 codebook represents 8 exactly? Which represents 2.5 exactly? Which would give the nearest nonnegative represented value to 2.6 if nearest rounding is used? Restrict your answer to the listed codebooks.

Worked explanation

Only E3M0 contains 8. Only E1M2 contains 2.5. For 2.6, E1M2 chooses 2.5 (distance 0.1); E2M1 chooses 3 (distance 0.4); E3M0 chooses 2 (distance 0.6). Thus E1M2 has the closest codebook value for this particular input. This does not prove it is best for a tensor containing values up to 16: its maximum 3.5 would force clipping or another scale.

Scaled integers can imitate a fixed-step codebook: multiplying the integer set −8,…,7 by 0.5 gives −4,…,3.5. That set still differs from the sign-based E1M2 example, whose negative magnitudes mirror the positive magnitudes. The scale and the signed convention both matter; visual similarities between codebooks do not make the formats identical.

10 · Affine quantization chooses a scale and a zero point for an integer codebook

The final source page defines quantization as mapping a continuous or large set of inputs to a discrete set and identifies quantization error as the difference between input and quantized value. It does not provide an affine neural-network quantizer formula. Everything in this section is therefore a constructed mathematical extension of that definition, with its assumptions supplied here. [Review, page 98]

Assume an integer code q restricted to [qmin, qmax], a positive scale a, and an integer zero point z. Define dequantization, the reconstructed real value, by

x̂ = a(q − z)

The scale is the real spacing between adjacent integer codes. The zero point tells us which code means real zero: q = z gives x̂ = 0. Solving for the ideal real-valued code gives q* = x/a + z. It may not be an integer or may lie outside the code range, so encoding requires rounding and clipping:

q = clip(round(x/a) + z, qmin, qmax)

Here round means nearest with ties to even; clip limits the result to the specified interval. The formula deliberately rounds x/a before adding z. At exact halfway ties, ties-to-even rounding of x/a + z can differ when z is odd, because shifting by an odd integer changes the parity of the adjacent codes. These choices make every practice answer deterministic; other quantizers may choose different conventions. For example, at x/a = 3.5 and z = 5, this formula gives round(3.5) + 5 = 9, while round(3.5 + 5) gives 8. State the order as well as the tie rule.

Derive the endpoint scale and zero point

Suppose you want q_min to reconstruct a minimum real value x_min and q_max to reconstruct x_max. The two equations are x_min = a(q_min − z) and x_max = a(q_max − z). Subtracting eliminates z: x_max − x_min = a(q_max − q_min). Therefore a = (x_max − x_min)/(q_max − q_min), assuming x_max > x_min. Solving the first equation gives z* = q_min − x_min/a. A practical integer zero point requires rounding and possibly clipping z*. If z* is not exactly an allowed integer, both endpoints need not reconstruct exactly after that adjustment. Constant-valued calibration data also need a separate scale rule because the difference x_max−x_min would be zero.

Worked affine example: unsigned four-bit codes

Take q_min = 0, q_max = 15, x_min = −2, x_max = 5.5. This is a constructed range, not a slide experiment. Endpoint scale is a = (5.5 − (−2))/15 = 7.5/15 = 0.5. Ideal zero point is 0 − (−2)/0.5 = 4, already an integer in the range. Reconstruction is x̂ = 0.5(q − 4); q = 0 gives −2, q = 15 gives 5.5, and q = 4 gives zero.

Increasing the range while keeping the same code count increases the spacing, so it can reduce clipping while increasing ordinary rounding error.

Practice 11 · Change the input without changing the quantizer

Using a = 0.5, z = 4, and codes 0,…,15, quantize 1.1. State the ideal scaled input, stored code, reconstruction, and signed error.

Worked explanation

x/a = 1.1/0.5 = 2.2. Round to 2 and add 4: q = 6. Reconstruction is 0.5(6 − 4) = 1. Signed error is 1 − 1.1 = −0.1. There is no clipping because q is inside the code interval.

Practice 12 · Change the scale and encounter a tie

An unsigned four-bit quantizer has a = 0.2 and z = 5. Quantize x = 0.7 using nearest, ties-to-even rounding. What changes if the question had instead specified ties upward?

Worked explanation

x/a = 3.5 exactly. The stated round-before-offset convention rounds 3.5 to 4, so q = 9 and x̂ = 0.2(9−5) = 0.8. If a different question defined q = round(x/a + z), ties-to-even would round 8.5 to 8 and reconstruct 0.6; that is a different quantizer convention. Ties upward also chooses 4 here, so this particular result is unchanged. The tie policy still matters in general: a tie at 2.5 would round to 2 under ties-to-even and to 3 under upward ties. Do not claim this example proves tie rules always agree.

A symmetric extension sets z = 0. For a four-bit illustration, choose codes −7,…,7 deliberately, leaving the two’s-complement −8 code unused, and cover real magnitudes through 3.5. Then a = 3.5/7 = 0.5. Input −1.2 gives round(−2.4) = −2 and reconstruction −1. This convention is common enough to motivate the mathematics but is not specified by the source’s INT4 picture; the unused code and scale are assumptions in our exercise.

11 · Representation error and model error are different measurements

Define signed reconstruction error ε = x̂ − x. Its sign tells you whether the reconstruction is above or below the input; |ε| measures its magnitude. For unsaturated nearest rounding on a uniform grid of spacing a, the nearest code lies at most a/2 away. Therefore |ε| ≤ a/2, provided clipping is inactive. This is a statement about this scalar quantizer, not about a neural network’s final accuracy.

The three unsaturated worked affine inputs have errors −0.2, +0.2, +0.2. The mean squared error (MSE) is the average of squared errors:

MSE = (0.2² + 0.2² + 0.2²)/3 = 0.04

The input 6.2 has absolute error 0.7, larger than a/2 = 0.25, because saturation is active. The half-step bound is not wrong; applying it outside its assumptions is wrong. Similarly, a small scalar MSE alone does not establish preserved task accuracy. Different parameters or activations can influence a model’s outputs differently.

Low-bit storage can reduce the raw value bytes. For P stored values and bit width b, ideal packed storage is Pb/8 bytes. One million values need 4,000,000 bytes at 32 bits, 1,000,000 bytes at 8 bits, or 500,000 bytes at 4 bits. These are 4 MB, 1 MB, and 0.5 MB using decimal MB = 10⁶ bytes. The formula excludes scales, zero points, alignment, and other metadata. It also assumes four-bit packing rather than allocating a full byte per four-bit value.

The arithmetic savings are constructed storage calculations. They do not establish a four-times speedup, an eight-times speedup, or a latency number. Actual performance depends on how the hardware and implementation store and execute the format, and on which part of the application dominates runtime.

12 · Mixed practice asks you to choose the formula before substituting

These questions preserve the review’s sentiment: interpretation, basic calculation, and explaining what a format buys. They change the input values and require the same core reasoning; optional boundary and rounding questions are labeled extensions rather than silently raising the source example’s difficulty.

Practice 13 · Conceptual, same difficulty

Two formats both use 16 bits. Format A has 5 exponent and 10 fraction bits; format B has 8 exponent and 7 fraction bits. Which better preserves small differences around 1? Which reaches more exponent scales? State the tradeoff without claiming either guarantees better model accuracy.

Model explanation

A has more fraction bits, so its local spacing around 1 is 2⁻¹⁰ rather than B’s 2⁻⁷; it better resolves small differences there. B has a wider exponent field, so it reaches more scales. Neither fact alone specifies the distribution of the model’s values or its sensitivity to representation error, so it does not establish model accuracy. A complete answer connects each bit field to its own consequence.

Practice 14 · Boundary reasoning extension

A student says, “The largest FP16 subnormal equals the smallest FP16 normal because their decimals round to the same display.” Explain the mathematical error and give the exact gap.

Model explanation

The exact largest subnormal is (1−2⁻¹⁰)2⁻¹⁴ and the smallest normal is 2⁻¹⁴. Subtracting gives 2⁻²⁴, a positive difference. A rounded display can conceal distinct bit-pattern values; it does not prove equality. Exact powers are preferable in boundary questions.

Practice 15 · Quantization interpretation extension

In x̂ = 0.5(q−4), a student says code 0 means real zero. Identify the error, give the code for zero, and explain why x = 6.2 does not satisfy the half-step error bound.

Model explanation

Code 0 reconstructs 0.5(0−4) = −2. Real zero uses q = 4. Input 6.2 needs an out-of-range code and is clipped to q = 15, giving x̂ = 5.5 and error −0.7. The half-step bound applies only to unsaturated nearest rounding, so it cannot be used for this input.

Practice 16 · Short answer, same difficulty

Why does increasing exponent width while decreasing fraction width often improve range but worsen local precision? Use one formula and one numeric comparison from the workbook.

Model explanation

The exponent selects the scale 2^(E−β), while m fraction bits determine the local step 2^(k−m). With the same 16-bit total, BF16 allocates more exponent bits than FP16 but only 7 fraction bits instead of 10. At [1,2), BF16 spacing is 1/128 and FP16 spacing is 1/1024, an eightfold difference. This explains the source’s range/precision comparison without asserting a measured accuracy result.

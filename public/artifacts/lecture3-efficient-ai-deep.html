Counting What Makes a Network Expensive

Most people count parameters and assume that is the cost of a network. Lecture 3 shows that the number that usually bites is memory for activations, and that speed and throughput are different measures. It then builds the convolution layer that produces both.

Parameters are not the memory bill

A network's parameter count is the number of weights and biases it stores. The lecture's first efficiency claim is that this number is not what limits inference. The slides say that #Activations, not #Parameters, is the memory bottleneck in CNN inference, and the same holds in training. [Lecture3, slides 44, 46]

Weights sit in storage once. Activations are rebuilt for every input, and a single layer's activations must fit in memory at the same time.

The rest of this page follows that idea. It counts parameters, counts activations, and then shows what happens when the memory limit is a microcontroller's 256 kB. [slide 45]

Latency and throughput answer different questions

The slides define latency as the delay for one specific task, and throughput as the rate at which data is processed. [slides 32–33] They then compare two designs for the same workload, four images at 100 ms each. Design 1 processes one image at a time, and Design 2 runs four in parallel. [slide 34]

DesignImages in parallelLatencyThroughput
Design 1150 ms20 images/s
Design 24100 ms40 images/s

The two measures matter for different products. A camera app that must answer one frame quickly cares about latency. A job that labels a large batch of photos overnight cares about throughput. The slide's example is designed to show that the two can move in opposite directions, so a design chosen for one may be wrong for the other. This paragraph is general reasoning, not a result from the slides.

Design 2 doubles throughput while making each image wait twice as long. Higher throughput does not mean lower latency here. The slide asks both questions, "does higher throughput translate to lower latency?" and "does lower latency translate to higher throughput?", and the answer depends on the design. [slide 34] A model that is fast for one input can still be slow overall, and the reverse is also true.

Counting parameters means counting weight tensors

Every layer stores a weight tensor. For a convolution the slides write its shape as W : (co, ci, k, k), one k×k kernel for each pair of output and input channels. [slide 17] The same counting rule gives the parameter count for each layer type. [slides 38–40]

Layer#Parameters
Linearco · ci
Convolutionco · ci · kh · kw
Grouped convolutionco · ci · kh · kw / g
Depthwise convolutionco · kh · kw

AlexNet, the slides' worked example, has about 61 million parameters in total, with bias ignored. [slide 48] The three linear layers hold most of them. The 4096 × 9216 layer alone has 37.7 million weights. The three together hold about 58.6 million of the 61 million, or 96%. The convolution layers are small by comparison.

The formulas also show how design choices move the count. In every row the output channel count co is a multiplier, so doubling it doubles the parameters of that layer. Grouping by g divides the count by g relative to a dense convolution with the same channels. These are direct readings of the table, not measured results. [slides 38–40]

Because the parameter count is dominated by linear layers, it says little about the memory a convolutional network needs while it runs. That is the lecture's reason for counting activations separately.

Counting activations means counting what must be held at once

An activation is the output a layer produces for one input. For AlexNet the slides count 150,528 values in the input image (3 × 224 × 224), 290,400 in the first convolution's output (96 × 55 × 55), and 932,264 in total across all layers. [slide 49] The peak is roughly the input plus the output of the largest step: 150,528 + 290,400 = 440,928 values. [slide 49]

A flow diagram makes the difference clear. Weights are read from storage, activations are created and destroyed for each input, and the peak has to fit the device.

The arithmetic makes the point. The first AlexNet convolution's output, 290,400 values, is about 1.9 times the input image's 150,528 values. That layer has far fewer parameters than the first linear layer, which holds 37.7 million. Memory cost follows the shape of the feature map, which depends on the spatial size and channel count, rather than the parameter count. [slides 48, 49]

On a microcontroller, the peak layer decides everything

The MCUNet work on IoT devices shows where memory actually goes. For MobileNetV2 the slides plot memory per block. Block 2 peaks at 1,372 kB, while the microcontroller limit is 256 kB. [slide 45] However few parameters the model has, a 256 kB device cannot hold that block's peak memory.

The per-layer view in MCUNet shows the pattern more fully. Early layers have high activation memory, late layers have high weight memory, and the middle layers have low memory cost in both. [slide 47] A design that balances the two is what makes a network fit.

Convolution is where both numbers come from

A convolution slides a small kernel over the input and computes a weighted sum at each position. [slide 14] That is the weighted-sum neuron from Lecture 2, repeated across space. Slide 14 shows one photo filtered by four different 3×3 kernels, edge detection, blur, and sharpen among them, giving four different features. Each kernel is a small set of weights, so one convolution layer holds many filters, and each filter produces one output channel. [slides 14, 17]

Stride controls how many positions the kernel visits. On a 5×5 grid, stride 1 visits 25 positions, while stride 2 visits 9. [slide 22] A 1D convolution slides along one dimension, such as time, and a 2D convolution slides along height and width. [slide 12] Grouped and depthwise convolutions reduce the parameter count, by dividing by g or dropping the input-channel factor. The table above shows both. [slides 23–24] Pooling shrinks a 4×4 map to 2×2. [slide 25] Most common activation functions have no learnable parameters. [slide 27]

Which number is the bottleneck?

Before optimizing, ask which resource is short. If the model must fit in storage, the weight count is the question, and the linear layers of AlexNet are where to look. If the model must fit in RAM, the question is the peak activation step, as in the MobileNetV2 figure. If the model must answer quickly, the question is latency for one input, and if it must process a large queue, the question is throughput. The same network can be fine on one of these and fail on another. This checklist is a reading of the lecture's framing, not a method the slides state in one place.
